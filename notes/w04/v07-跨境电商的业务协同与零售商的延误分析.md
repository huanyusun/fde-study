# V07 跨境电商的业务协同与零售商的延误分析

> 视频 24:00(article 1031545,课件 16 页;字幕稿 `transcripts/v07-*.md`)。外部案例课:两个数据接入案例,分别讲"系统对接怎样长成业务协同"与"数据有了为什么还要反复核实"。配合材料包 C12、C04 案例卡阅读,一遍过。

## 核心方法与机制

1. **两个案例的选取逻辑**:都涉及数据接入,都落在具体业务任务上(补货发货 / 解释门店收货延误),正好配合本周 ETL 与第一个 demo 的方法。案例材料分别来自国内服务商的公开分享和供应链 FDE Samir Saci 的文章,均为转述,不是讲师亲历。
2. **跨境电商案例背景**:服装电商按颜色×尺码管理 SKU,多平台开店;库存汇总在聚合 SaaS,业务信息在飞书,补货计算用 Excel。工具不少,但数据靠员工手动搬运——"打通两个系统"是这个背景下提出的。
3. **"打通系统"的真实含义**:FDE 用多轮沟通加操作录屏看清员工日常,把模糊需求具体化成三件具体工作——工厂发货照片的人工识别录入、按公式取数填表生成补货 PDF 订单、库存与广告投放脱节(缺货还在投广告)。
4. **保留客户的核心竞争力**:补货规则是客户按销售情况自己积累的判断逻辑,FDE 沿用不重写;工作放在取数、填表、订单整理这些环节。Agent 负责取数并调用原规则算补货,人工核对后生成 PDF 订单发供应商——典型的 AI 与人分工。
5. **接口的现实条件决定方案**:API 看起来能用,但密钥机制不支持多团队共享(一个团队刷新,另一团队的密钥失效),接口还有额度限制。解法是加中间数据库:统一程序访问 SaaS 管理密钥,各团队从中间库取数,同一份数据只提取一次。"ETL 中对原始数据流做改造"在这里是常态。
6. **数据流向跟着客户的工作习惯走**:客户习惯在飞书处理业务,就把库存数据同步到飞书;数据位置、接口权限、要支持的使用方式三者决定数据流设计。
7. **演示要演完整链路**:照片识别回填后有人工最终确认;给客户演示时必须把识别、回填、人工确认一起演,不能只演"AI 能认图"。
8. **教学分析的 demo 设想(案例卡)**:限定一小批商品,取"聚合 SaaS 取数 → 中间库 → 飞书 → 按原规则算补货 → 人工核对 → 订单草稿"这条窄而完整的链路;请客户对照自己的人工计算结果查遗漏;草稿不实际发送给供应商;若 SaaS 在线接口没调通、先用导出文件替代,必须明说在线同步尚未验证。
9. **米兰零售商案例**:规划员要向门店解释收货延误;项目整合仓储、运输、规划工具三套系统的时间记录。两处具体核实——①订单创建时间:多个日期字段仅凭名字分不清,把业务界面信息与后台记录交叉核对,确认自动创建和人工创建的订单取不同字段;②装车延误责任:仓库与运输部门解释不一,取决于货是否备好、车是否到达、是否第三方货代,FDE 反复核实后才形成可用的分析规则。
10. **让真实使用者核对结果**:字段定义明确后整理成表,通过 MCP 工具交给 Claude,工具描述写清字段含义与业务规则;规划员用自己日常的分析任务使用 Agent,能发现偏离问题、遗漏条件、结论不符——这是内部检查得不到的反馈。
11. **阶段性成果 ≠ 业务效果改善**:跨境电商项目交付后客户收回了数据访问权限,服务方拿不到营收、广告成本和利润数据,无法量化最终业务改善;米兰案例也只有规划员认可的过程记录,没有正式验收和长期收益。结论必须有证据支持,不夸大对业务效果的影响。
12. **字段有值不代表含义明确**(C04 教学判断):模型通过工具取数时,也需要知道字段含义和相关规则;不能仅靠字段名、通用规则或模型猜测业务判断。

## 与青禾沙盘的连接点

- 对应第 11 步 demo 选线:窄而完整、限定小范围、给客户对照的依据(人工计算结果)、不实际执行外发动作、替代路径如实说明——这就是 demo_plan.md 里"最小验证链路 + 结论限定"的案例版。
- C04 的字段核实对应第 3–5 步:订单创建时间的多字段歧义,正是青禾剖析时要做的字典差异三类判断(映射错误的典型);装车责任规则的形成过程,说明清洗规则和覆盖说明的依据要从访谈来,不从字段名猜。
- "交付后收回数据权限"提示:老周已声明数据仅限项目环境使用、结束后按规定删除——我们的覆盖说明和结论都要按这个边界写。

## 可用于作业的证据 / 判断

- demo 的价值是让客户在完整链路里指出"不对"的地方(漏了条件、算得不一致),不是展示功能完美——第 11 步跑 demo 时保留 bad case 正是为了这个。
- 演示前先想清楚"客户拿什么对照":青禾 demo 的问题要有完整时间范围,结果要能和小林/沈总已知的口径对上。
- 项目汇报里区分"流程跑通"与"业务改善":W04 交付里 demo_run.json 证明的是链路可运行,不是复购率提升了。
