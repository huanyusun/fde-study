# V08 本周作业怎么做

> 视频 9:03(article 1031543,课件 8 页;字幕稿 `transcripts/v08-*.md`)。操作说明:材料位置、代码入口与提交前检查方法。第一遍看知道从哪下手,完整步骤以《W04 任务书》作业路线为准。

## 核心方法与机制

1. **入口与核心参考**:材料包 `00_使用说明.md` 写明工程包、青禾数据、客户材料位置;核心参考是 `05_作业任务书.md`(操作步骤+提交要求),视频只提醒注意点,不重复任务书。
2. **环境准备**:在**新目录**解压新工程包(`fde-agent-w04-0.1.0-e15-c4`,凭包内 MANIFEST `package_revision=agent-large-dictionary-20261105` 确认),按工程根目录 README 完成环境检查(`tools/w03.py doctor`)和工作目录初始化(`tools/w04.py init --workspace .`)。
3. **承接 W03**:拷贝上周业务模型、可执行的指标定义(含配套模型与 SQL)、访谈记录;W03 原提交保留,在其副本上继续。没完成 W03 的从 W03 checkpoint 开始,但必须写明采用了哪些部分——照抄不算完成 W03。
4. **代码入口**:`customer/w04/solution.py` 三个函数——`profile`(数据剖析)、`adapt`(按清洗规则处理数据)、`reconcile`(计算对账结果);自己的测试写 `customer/w04/test_solution.py`。命令行工具、文件读写编码、导入、查询引擎、运营 Agent 都是课程提供的,不用写。
5. **空白入口会报错**:`solution.py` 未实现时直接跑报 `W04_PROFILE_UNIMPLEMENTED` 等,这是正常表现;`test_solution.py` 默认有一个待补充的失败测试,要先改写(`W04_TESTS_UNIMPLEMENTED`)。推荐用 coding agent 辅助,但输入要先确认、产出用测试和对账验收。
6. **非 Python 路线允许**:用其他语言实现可以,但交付文件与报告要符合任务书格式,提交源码、测试方法、重跑说明,接受同一套检查。
7. **动手前先跑梧桐例题**:`examples/w04/wutong/` 下有 README 写阅读顺序;`replay.py` 重放 start、complete 两份快照(空白实现报 UNIMPLEMENTED 属正常,complete 快照每类 balanced 为 true);单元测试应 OK;反例脚本四项通过。梧桐字段名、备注写法、问题形态与青禾不同——看结构,不照搬规则。
8. **数据与记录纪律**:原始 CSV 完整保留,清洗适配结果另存;判断依据随代码同步写,不事后凭记忆补;改业务模型/指标记录前后与证据,未改的也注明核对结果;核实不清的保留待核状态。
9. **小林工作账只用于对照,不导入查询库**:至少选一条与 CRM 记录对照,结果写进 `docs/w04/data_diagnosis.md`;两边不一致列为待核实事项,找对应客户角色核实,不能凭工作账单方下结论。
10. **demo 要实际运行**:demo_plan 写完后,在导入后的青禾库上用运营 Agent 实跑,保存提问、回答、查询与结果并注明位置;调优前后对照,每次只改一处,没改善也如实记录——不可只留调优后的单一回答。
11. **预检分层与回查**:提交前跑 `tools/w04.py check --workspace . --output <新文件>`;预检报 **documents 层**未通过时,回 `docs/w04/` 对照 `templates/w04/documents/` 模板补文档(如 data_diagnosis.md 章节标题被改也会挂);预检只查文件与章节结构,**不判断内容真实性**。
12. **预检通过也要人工抽查**:比如 demo 方案里声明链路已跑通,要回实际查询和结果核实是否支持该结论,不支持就改结论;助教提交后会用 agent 或人工抽查文档结论有没有依据。

## 与青禾沙盘的连接点

- 本节是 12 步作业路线的操作导览:第 1 步环境与承接(解压、venv、`tools/w04.py init`、数据放 `materials/data/`)→ 第 2 步梧桐验证 → 第 3–8 步在 `customer/w04/solution.py` 实现 profile/adapt/reconcile + 自测 → 第 11–12 步 run-demo、调优、`tools/w04.py check` 预检 → 打包(只含 `customer/w04/`、`docs/w04/`、`artifacts/w04/`)→ 解压到新目录再 check 自查一遍。
- 失败目录(run-01 报错)留作诊断,换 run-02 重跑,不删目录续跑——对应"每条记录去向可解释"的纪律。

## 可用于作业的证据 / 判断

- "算完成"清单照任务书第 1.5 / 2 / 12 步的返回值核对(doctor 无缺依赖、read 列出 6 个 CSV 及条数、两次 check 都 `passed: true` 且 `manual_review_required: true`)。
- 预检各层的回查路径:documents 层查文档模板标题;execution 层用公开样本(`examples/w04/public-check/raw`)单独跑 adapt 看实际报错;profile/records/provenance/coverage/reconciliation/repeat 各层对照 `expected.json` 与报错对照表。
- 提交前确认包里没有密钥、`.venv`、`.runtime`、课程原始数据。
