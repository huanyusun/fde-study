# V02 POC、试点和正式项目

> 视频 31:22(article 1031538,课件 23 页;字幕稿 `transcripts/v02-*.md`)。概念课:给下周 demo 在项目里的位置定位——不是 POC,也不是验收。

## 核心方法与机制

1. **demo 与 POC 不是一回事**:demo 是展示形式,售前、POC、试点、正式项目里都可以有 demo;POC、试点、正式项目是项目的**阶段**。判断自己处在哪个阶段,决定了要证明什么、交付什么、合同怎么签、成本谁担、该投入多少。
2. **三阶段对照**:POC(概念验证)回答关键假设能否成立、技术上是否可行,范围窄,一个场景+样例数据即可,不必处理所有边缘情况;试点验证在真实环境中部分真实用户能否用起来并产生业务价值,范围受控(用户、数据、时间、业务范围都有明确限定),要嵌入客户真实工作流、妥善处理常见边界情况并有兜底,结果接近实际应用版本;正式项目保证系统在客户环境长期稳定运行并扩大使用范围,通常由客户运维,要满足安全合规,配异常处理、监控、压测、回滚,最终移交给客户团队。
3. **阶段与合同不一一对应**:POC 通常在签约前,国内多数情况成本由乙方承担(银行付费 POC 的例外:之前项目吃过系统性能的亏、行业内能解的乙方少,甲方付的钱也只覆盖人力差旅);试点一般单独签合同,约定效果不佳时的处理(终止并支付基本成本),有时与正式合并为一个大合同分阶段执行、试点不达标甲方有权终止;正式项目必须签正式合同,可分期。已进正式项目后,依据不足仍可协商补调研/POC/试点。
4. **Palantir 路径**:先做几天实操研讨会,签付费试点逐步扩大使用范围,最终到公司级合同;招股书自述常以零成本或低成本提供短期试点,把客户风险降到最低;年报同时风险提示——试点成功也不必然签下更大的正式合同。
5. **AI 时代各阶段关注点变了**:传统软件 POC 验证功能与方案一致、性能扛得住数据规模;AI 时代的 POC 关注 agent 能力能否嵌入业务流程解决实际问题(AWS 高管:许多生成式 AI POC 只验证了模型功能性,没评估商业价值);传统试点看系统稳定性和用户体验,AI 试点看 agent 在真实业务中的执行表现——持续监控、人工复核结果、收集反馈、把问题转成评估案例(OpenAI/Anthropic 都建议小范围试点+人工监督)。
6. **AI 时代的另外三个变化**:上线后系统行为会随底层模型和 Harness 变化而变(换模型要采取措施,OpenAI/微软都有建议),且调用模型产生持续运营成本——传统私有化软件这部分几乎可忽略;验收签字即定型的模式不再适用,FDE 要持续投入到把 agent 的回流和迭代交接给用户;可运行 demo 的制作成本大降(coding agent),硅谷顶尖 AI 团队首次见客户不再用 PPT,Palantir 直接在客户数据上现场演示。
7. **先试再买的底层逻辑**:传统 To B 的根本错配——乙方交付的是工具,甲方要的是结果;工具验收后能否用好、改造组织流程、产生业务效果,风险全在甲方,所以甲方用压价、定制要求、拖尾款自保,先试再买是同一种自保。方案表态无成本,实际使用有时间成本,**能运行的产品更难掩饰真实效果**。Gartner:自称做 AI 的企业数千家,真做 Agent 的仅约 130 家,很多是聊天机器人/RPA 改名——甲方只能靠试用来判断。乙方承接试用=把客户的部分风险转到自己身上,敢接说明对效果有信心且能控制成本;AI 时代做可运行项目成本大降,这件事变得更容易;且一旦有一家同意先试后买,别家很难不跟进。
8. **客户对 demo 点头的含义**:签约前的点头=可以继续推进(进入试点/谈 SOW),此时没签约没批预算,不关键;签约后的点头=愿意继续配合推进当前方向,**不等于验收**——验收按合同和 SOW 规定来。客户满意 demo 不代表一切,但不满意可能影响整个项目。售前说服客户签约即完成;FDE 的成功要等到业务指标实际改善(OpenAI 招 FDE 的两条:负责从原型到稳定生产的技术交付;以生产环境实际应用效果和对客户工作流程的影响评估成功。Anthropic:早期测试可用但未达到隐含期望,不算成功)。
9. **客户满意 demo 之后干什么**:趁势明确工作范围、预算投入、成功标准、结束条件——正好用 W01 立项判断那套。成功验收不是一次确认,而是可以安排的具体工作。

## 与青禾沙盘的连接点

- **青禾的位置**:W03 用老周的测试库跑通查数流程≈签约前的技术验证;上周末已签正式合同和 SOW——现在是**正式项目第一期**。下周 demo 是正式项目里的**首次阶段检查**,不是 POC,也不是验收。
- 但分量不轻:沈总不满意会影响合同执行,更会影响沈总及老周等人对项目组的信任和配合;企业通常只愿尝试一次 AI 产品,首次演示尤其重要。
- 演示基于本周客户提供的真实数据——呼应"AI 时代关注 agent 在客户真实数据和流程上的实际能力"。
