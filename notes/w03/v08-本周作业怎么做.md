# V08 本周作业怎么做

> 视频 11:55(article 1028701)。W03 作业(让运营 Agent 按青禾口径查数)的操作总地图;步骤细节以 `course-materials/w03/05_作业任务书.md`(12 步 + 作业路线)为准。字幕稿本地见 `transcripts/v08-本周作业怎么做.md`(不进 Git)。

## 核心方法与机制

**本周主线**:补充访谈 → 更新业务模型 → 构建 Skill 生成 38 项指标 → 两步测试 → 带证据与王经理讨论 SOW → 分五组提交。

1. **承接上周,不覆盖**:W02 提交过的目录环境原样保留(每周一个快照),工程包解压到**新目录**并配 Python 环境;上周业务模型文件复制到本周文档目录作起点——缺起点文件时包内有参考业务模型,**用了要注明**,不能当自己的访谈成果。
2. **跑通梧桐样例再开工**:确认模型 API、依赖、加载、聊天入口都正常;环境问题先用它排查。
3. **列缺口再访谈**:按任务书第三步对照材料列缺口,写明每条缺口影响哪些指标、该问谁。已写明的客户诉求和指标口径不必重问;**未写明的规则严禁凭常识补**,必须访谈确认。
4. **王经理本周必访,而且要早**:不等 SOW 初稿写完——提前问阶段交付的验收依据和双方责任要求;草稿出来后在**同一会话**继续讨论其他信息需求(访谈次数有限,客户不陪聊)。
5. **未决的处理**:未明确的问题标为未决;未决指标不进指标库,而作业要求 38 项全部可执行——所以未决的要回到补事实那一步,更新输入重新生成。已明确的 32 项不必逐一问。
6. **Skill 开发纪律**:工作空间写 `skill.md`(可自定义实现,改 `build.json`),先试跑几个指标确认方法可行,再生成全部 38 项。**只改中文目录、不写构建 Skill、直接粘贴生成结果 = 未完成作业**。逐项核对每个指标定义有原文或客户答复作依据,写入指标核定记录。
7. **一对多陷阱**:清河一个会员可有多张卡,每张卡各有开始日/结束日——按卡处理日期,别按会员。有效期口径和哪些计入单点以清河业务工作为准。
8. **测试两步走**:小样本(可手算核对,用来调期望值和判定)→ 规模数据回归(专门项目,覆盖任务书指标,记录环境与配置)。测试集和判定程序**自己写**——默认判定程序未实现会报错,梧桐样例只处理单指标单行,不能照抄。仅展示 SQL 不算数,**必须真正执行出结果**。
9. **人工核对解释文字**:Agent 除数值外会给一段口径/条件的文字解释,判定程序不比这段,**要人工核**;不符就按 V07 的方法逐层定位。
10. **改了就全量复测**:修改 Skill 或业务输入后,必须重新生成 + 重新加载,再跑一遍。
11. **SOW 的边界**:初稿自己写,带草稿+验证证据(访谈记录、测试报告、失败修正记录)找王经理——请他提意见,不代写;他从财务合同核查角度对范围、责任、验收依据提意见。分歧和未确认事项记录下来,注明修改或保留未决。修订后**可直接提交,无需王经理 agent 批准,也不需向沈总汇报**。
12. **提交形态**:所有产出放同一个客户交付仓库,按任务书第三节分五组;每轮构建/加载/测试用新目录,**保留失败记录不覆盖**;选一份测试报告复制到表格。`check` 命令只是预检,助教会用独立问题和错误结果复查。

## 与青禾沙盘的连接点

- 本周 Agent 对象:标准会员运营 Agent 按青河/青禾口径真实查数;指标库 + 清河小样本数据一起加载后重启 Agent,从聊天入口查询。
- 访谈对象:王经理升为必访(验收依据、责任划分);访谈 agent 刚开发可能不稳,**出错就刷新页面或重置原问题**,别重新发问/新建会话(扣 quota)。
- 遗留机制:访谈遗漏导致阻断时,本周会按情况分发补充材料。

## 课件补充(11 页结构)

- **五阶段划分**:领取与起点(步 1–2)→ 访谈与模型(3–5)→ 构建与问数(6–8)→ 测试与修正(9–11)→ SOW 与提交(12 及第 3–5 节)。
- SOW 草稿讨论的**粘贴示意**(借 V02 查数项目,非青禾内容):草稿相关段落 + 证据摘要(查询总数与期望一致、门店分组有误属原承诺范围已修正)+ 具体问题("门店分组修正后的查询结果,由您按测试包核对后再计入 M2 验收材料,这样写是否可以?")——问句式、有证据、有具体动作。
- 提交表与任务书第 3 节一致;**check 只是预检,助教另用独立问题和错误结果复查**;构建/加载/测试每轮新目录,失败记录保留不覆盖。
- 卡住以后表:环境问题重跑梧桐样例;缺业务事实继续访谈;访谈遗漏阻断→课程方可能分发补充材料(标课程方来源、不充抵必访);访谈网页出错→刷新页面或点"重试原问题",不重新发问不新建会话(不重复扣次数);对照任务书自检后提交,遇到问题找老师和助教。

## 可用于作业的证据 / 判断

- **提交前自检**:对照任务书第四节 + 两个指南末尾的自检清单逐项检查;助教独立复查,预检通过 ≠ 内容正确。
- 证据链要求:每个指标有依据(原文或客户答复)→ 指标核定记录;测试有小样本手算核对 + 规模回归 → 测试报告;失败与修正保留 → 失败修正记录;SOW 条款有王经理意见记录(分歧与未决如实标注)。
- 判断纪律和 W02 一脉相承:不凭常识补规则、分歧不消除只记录、改配置必须复测——这正是任务书「作业路线」与 12 步的底层逻辑。
