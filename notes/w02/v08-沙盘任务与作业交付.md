# V08 沙盘任务与作业交付

> 对应 lectures/w02 PDF(9 页),2026-10-26 听读。本周作业的操作总地图,反复对照用。

## 五步作业路径

### 第一步:访谈并保存原始记录
- 准备:读材料使用说明、任务书、旧项目结项材料(PPT)、背景补充、本周访谈对象;找到自己 W1 立项报告和 fit-gap 快照,**列出本周要核实的问题**
- 访谈:必访老周(IT)、小林(会员运营)、陈姐(店长);王经理(财务)选访。结合职责与已有回答继续追问;不同说法先标记线索、追问依据
- 保存:结束后导出「提取用记录」放进客户仓库;先取得原始材料 → AI 提取候选 → 集中核查

### 第二步:选择开发路线并运行提取
- 两条等价路线(按相同业务产出和证据要求判分):
  - **路线一**:修改课程工具——沿用其读取、调用、核查停点、记录保存能力,按自己业务需要改提示词/Skill/必要代码
  - **路线二**:开发自己的 Skill(可借助 coding Agent);Skill 只负责提取、核查、模型维护,知识问答沿用课程工具
- 使用课程工具时的配置:
  1. 初始化文档:缺业务模型/核查记录时工具按模板创建;模板只有结构,内容来自访谈、提取、核查
  2. 配置本轮任务:`customer/w02/extraction.json`(sources=访谈记录路径,初始为空;focus_questions=本轮重点问题)、`customer/w02/workflow.json`(goal=本轮目标)
  3. 运行提取工具取得候选;旧项目 PPT 只用于理解背景,不用提交

### 第三步:核查候选 → 确认业务模型
- 对照访谈原文核查:遗漏?改变原意?丢失条件?决定采用/修订/暂不采用,**把理由反馈给 AI**
- 分组核查;已核查的沿用并引用记录,新增或变化的再核查
- 发现方法问题:改提示词/Skill/代码后重跑,固定材料、模型等条件比较前后;没改善也如实记录
- 分歧处理:写清各方说法、来源、时间与适用范围是否一致、还需谁提供什么依据;**区分口径差异 / 共同未知 / 不同判断 / 相互矛盾**;客户分歧不能靠改提取工具消除
- 工具起草《业务模型说明》草稿(范围、对象及定义、关系、规则),学员审阅:是否准确表达业务认识、保留分歧与未知、关键建模选择有依据;确认后保存

### 第四步:提供模型,检查 Agent 回答
- 通过工程包**知识问答入口**把确认后的业务模型交给标准会员运营 Agent
- 问题要检验**客户特有知识**,不提前写预期答案;对照命令生成同一问题「未提供模型/提供模型」两组回答
- **先核对请求(实际带上了模型),再检查回答**(正确使用知识、保留条件与未知);未提供组也可能答对,按实际差异判断
- 程序保存业务模型副本、请求、回答;有问题按原因改(业务模型/加载配置/问答提示词)后用原问题复查

### 第五步:保存判断,更新 W1 产出
- 《访谈与核查记录》:访谈目的、核查取舍、提取方法设计与验证、Agent 回答检查结论;当前理解与下一步(向谁取什么证据);干系人地图放这份记录;已核实与待验证分开
- 更新自己 W1 立项报告和 fit-gap:**保留 W1 原版**,只改受新证据影响的条目,说明改了什么为什么改;没改也说明核对依据;未解决问题留到 W3(指标、范围、SOW)

## 提交前自检四问
1. 访谈是否取得具体有用的信息?
2. 采用的信息是否有依据,并保留适用条件?
3. 业务模型是否清楚,能否结合访谈材料说明对象、关系和规则的定义理由?
4. 标准会员运营 Agent 是否实际使用了这些认识?

⚠️ 预检通过 ≠ 内容都正确,老师会人工/AI 审阅。

## 与青禾沙盘的连接点
- Agent 对象是「标准会员运营 Agent」;业务模型喂给它的知识问答入口
- 图书馆示例(青橡图书馆:借阅/读者/馆藏副本)只示范方法,须另解压一份工程包运行,不占用青禾配置

## 可用于作业的证据 / 判断
- PPT 示例中的字段结构可复用:候选(CLAIM)带「来源 MSG 编号 + 原始证据状态 reported + FDE 核查结论」三段式,访谈记录里照此组织核查
- 对照判读句式:「保留期限有前台『一天』口径与馆长『两天』理解,均未核实;自动提醒可用性未知」——分歧+未知的表达范式
