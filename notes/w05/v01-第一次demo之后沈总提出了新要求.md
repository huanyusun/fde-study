# V01 第一次demo之后沈总提出了新要求

> 视频 9:25(article 1036127,课件 7 页;字幕稿 `transcripts/v01-*.md`)。本周开篇定调:交代沈总的新要求与本周两块工作,动手前一遍过。

## 核心方法与机制

1. **demo 的预期应验了:客户看过才提得出具体要求**:上周把 CRM 原始数据导入数据库、核对处理前后结果、让运营实际查数,demo 展示会员复购分析、渠道首单及后续订单分析两条链路,沈总认可展示范围内的查询分析能力,随即对下一步提出具体要求——印证 W04 的判断:文字描述人人理解不同,跑一遍才能出具体需求。
2. **新要求是"从查数到帮人"**:agent 不止做数据分析,还要协助运营工作——识别值得关注的会员(尤其沉睡会员),并给出基于消费行为的具体建议。场景定为沉睡会员召回:要掌握会员过去一段时间的消费情况、最近一次购买时间、业务上的联系限制。小林工作账里已标记过一些沉睡会员,回访时客户却说"一直用老卡在门店购物"——系统判断与客户自述冲突。
3. **冲突的根因是双系统并存**:青禾同时运行新 CRM 和旧 POS。迁移只把部分 POS 会员迁入新 CRM 并建新账户,**历史消费记录未迁移**;旧 POS 在部分场景继续使用,新消费记录两边都在产生。上周拿到的数据只有新 CRM 的消费记录——所以"CRM 里查不到近期购买"不能说明这个人在所有系统都没买。
4. **本周两块工作**:①把新旧系统中同一会员的记录关联起来(ID-Mapping);②让标准产品的能力在青禾业务条件下可用,同时支持运营分析和门店查询。要准确判断沉睡,必须结合旧 POS 记录核查,并理清新旧账户间的关系。
5. **第二入口:门店 UI**:陈姐提出门店希望直接在页面上查会员资料和购买记录,而非通过 agent;沈总认可——并非所有操作都要走自然语言,确定性高的操作用 UI 更高效。老周(IT)补充:无论哪个入口,都要确认具体会员身份、追溯信息来源与关联记录;相同查询条件下 agent 和界面两个入口应保持一致。
6. **标准产品按自己的节奏迭代**:前几周产品已扩展通用查数和数据导入;本周新增会员分析和运营建议——从"只能查指标汇总"到"按条件筛选会员、获取其订单/门店/会员卡等关联记录";并接入业务知识检索,agent 按当前任务查找适用运营规则、结合会员实际提建议并说明引用依据。这些能力集成进原 agent 入口,UI 用同一套系统。
7. **标品通用、现场定制**:标准产品提供通用能力,在青禾实际使用需结合本地数据和业务规则进一步开发——正确关联同一会员在不同系统中的账户和消费记录,才能给出建议。由此引出 toB 常见概念(标品定制开发、二次开发,产品团队/项目团队 FDE/客户 IT 的分工),V02 展开。
8. **材料与访谈分工**:随包提供第一次 demo 纪要、新需求说明、旧 POS 数据,以及身份关联、运营对象核验、联系限制等业务知识说明。材料中明确的直接引用、优先级高;有歧义带着具体问题定向访谈:身份依据问老周,运营规则例外问小林,门店使用问陈姐;目标和优先级由沈总确认。
9. **交付的是能力,不是场景**:合同和 SOW 约定的是会员运营助手能力,正式验收在项目期末、按 SOW 进行;本周沈总提的沉睡会员召回只是用于落实和检验相关能力的具体场景,不能代替最终验收。

## 与青禾沙盘的连接点

- 沈总这轮要求落到需求说明就是五项能力:新旧身份关联、按条件筛选会员、查看会员及关联记录、提供解释与建议、多入口复用——第 1 步读材料按这张表逐项核对已有支持和缺口。
- 关键口径已给死:参考日 2026-09-01,窗口 2025-09-01(含)至 2026-09-01(不含),近 12 个月净消费≥3,000 元,沉睡=最近一次有效购买满 60 天(支付有效、实付大于退款)——材料已明确的不访谈,直接引用。
- "老卡购物"反馈的处理原则(需求说明第二节):不能忽略,也不能仅凭自述认定原判断全错,要靠补充旧 POS 数据核实——写进业务模型的数据核实一节。
- 多入口一致(陈姐/老周的要求)= 作业 B 组验证的出处:直接入口和运营 Agent 用同一个会员业务模块,相同条件和数据版本下结果逐项一致。
- 角色找法对应缺口清单"下一步"列:老周(身份依据、导出范围、记录状态)、小林(联系限制、运营例外)、陈姐(门店使用)、沈总(目标与优先级)、王经理(合同范围)。

## 可用于作业的证据 / 判断

- "CRM 查不到近期购买≠没买"是"为什么补旧 POS"的一句话依据,业务模型第一节"本轮范围改成 CRM 与旧 POS"直接引用需求说明第二节。
- 报告 `formal_acceptance` 保持 `false`:本周是过程交付,正式验收按 SOW 在期末——场景跑通不等于验收。
- "沉睡召回是代表性任务、不是筛选能力边界"(需求说明第一节、第五节):支持条件范围内换阈值/时间/门店应继续正确工作;范围外要求要说明哪一项不能处理,不能去掉这一项照常给名单——筛选条件不能写死成一份名单。
- 未决身份的口径 v01 已埋线:关联依据不足或冲突时保留待核状态和来源,不能为得到人数或名单强行合并——对应任务书判定第 2 条"未决对象明确单列"。
