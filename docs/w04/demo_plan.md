# Demo 方案

## 链路与选择理由

演示链路：**会员复购分析**——三个递进问题：月度复购购买人数、付费会员复购人数、复购率。

选择理由：①沈总明确要求"能跑起来的东西，最好跟会员复购有关"（03_沈总消息.md），复购是本期会员运营的首要关注；②该链路直接服务总部运营月报工作（付费会员月度口径是王经理核查的验收对象，W3 模型资格判定规则 1-4），月度复购人数是月报核心列；③指标库已具备完整支撑（monthly_repeat_buyer_count、monthly_paid_repeat_buyer_count、monthly_repeat_rate 均定义并在 38 项跑通清单中），最小验证链路就是"一个完整自然月＋一个指标"。

## 数据可用性、最小验证与已有证据

- 数据：run-02 适配产物（member_month_stats 派生表：月末付费资格＋当月有效订单），覆盖 2024-09-01～2026-09-01（不含）；复购口径=同一自然月内≥2 笔有效订单（paid 且净额>0）。
- 最小验证链路：project-c ＋ 1 个完整自然月 ＋ 1 个指标；每次运行留 trace（SQL、数据哈希、覆盖快照可回放）。
- 已有证据：run-01 复购购买人数 646 账户；run-02 付费会员复购 115 账户；run-03 复购率 11.80%（口径=月内复购÷月内购买，指标库内置定义）；全部 status=ok，结论均限定在已覆盖范围（账户口径、不含商城独立流）。

## 暂不覆盖范围与待验证条件

- 会员状态筛选未建模：无法回答"活跃会员"口径（R3 要求排除未激活 22,296），当前以全会员口径＋声明代替（run-05/run-06 调优对）。
- 复购的门店/渠道分组未验证；跨指标比率（复购人数÷在库会员总数）未支持。
- 线上商城独立订单流、退卡流水不在数据内，复购规模可能被低估。
- 待验证条件：①业务侧书面确认"活跃会员"口径（谁签发、以什么文件为准）→ 才能建模账户状态维度；②门店维度加入复购派生表 → 才能回答"哪些门店复购弱"。

## 判断说明：关键假设及继续、缩小范围、调整方向的条件

**关键假设**：①复购=同一自然月内≥2 笔有效订单（月内复购，指标库内置口径）；②统计单位为 CRM 账户（字典口径，不代表自然人）；③8 月为完整代表月；④付费资格按月末判定（W3 规则，SQL 端点与模型一致）。
**最小验证链路与选择依据**：单月、单指标、可回放 trace；链路命中沈总点名方向且验收方（王经理）有明确核查标准。
**已有证据与待验证条件**：38 项指标跑通＋6 次实跑（含 1 组调优对照、1 次覆盖外拒绝）为已有证据；"活跃"口径书面确认、门店分组需求为待验证条件。
**继续的条件**：复购数字被运营/王经理认可为月报口径 → 扩展付费会员复购的门店分组与趋势。
**缩小的条件**：若业务确认"复购率"应按在库会员为分母 → 当前 monthly_repeat_rate 口径不适用，缩回只报绝对数。
**调整方向的条件**：若业务要的是"跨月流失预警复购"（上月购买本月又买）→ 与月内复购不同定义，转建模新派生表，重新走最小验证。
