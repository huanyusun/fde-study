# 手工模型路径

普通文本编辑器和基础 Python 即可；AI 辅助可选。练习数据是独立造例，不是青禾客户答案。

1. 阅读 `examples/w05-linkml/business_model.md` 与字段对照，打开 `templates/w05/member.template.yaml`。
2. 将模板另存为 `member.mine.yaml`。只填三个 `classes.*.slots` 列表，删掉对应 TODO 注释。技术前缀、枚举、字段类型和连接配置已给出。字段／关系名应引用下面 `slots` 的定义，不能把业务规则写进 description 后期待执行。
3. 对照来源小表解释 M1 的三账户／两门店、X1 的未决身份及 POS 注册关系未知，再自行填写列表；已填例子 `examples/w05-linkml/member.filled.yaml` 可在完成后核对。
4. 运行 `python tools/w05_model.py --schema member.mine.yaml --data examples/w05-linkml/data.json --output .runtime/model-first`。使用新输出目录；生成文件和数据库均由命令生成。M1 应保留两个注册门店，POS 的注册外键为 null，X1 保持 unresolved。
5. 将数据路径改成 `examples/w05-linkml/errors/wrong-source-row.json`，在另一个新输出目录运行，定位 SourceAccount.source_row 错误；修正为原小表来源行号后再次运行。不要删除校验或手改 ORM。
6. 可选变更：在 Member.slots 增加 registration_reviewed_at，并在 slots 下定义 `range: date`、`required: true`；在自己的样本所有 Member 上提供来源可解释的日期。旧数据应拒绝，新数据应生成 Date 列并运行。它不是会员入会日期；正式青禾源表没有自动新增这个值。

正式客户工程将完成后的定义放在唯一入口 `customer/w05/member.linkml.yaml`，继续实现原三个 Python 函数，再执行 prepare → bind → init → service-call。练习已填 YAML 可作结构参照，不能替代业务核对。模板有 TODO 时 prepare 明确拒绝；三个客户函数未完成时仍拒绝。

固定来源映射由课程底座承接：Member.id ← member_id；display_name ← 原属性函数；identity_status ← 身份映射框架；source_accounts ← source_ids；registered_stores ← 属性函数的全部注册关系。SourceAccount 的命名空间、系统、文件、行号与注册关系来自现有源读取；Store 来自 W04 已接受门店表。来源字段的规范化、缺失、冲突及关系选择仍由原客户函数提供，不新增通用 ETL 工程。

新增本场景字段时，可从 `member_attributes` 返回可选 `model_fields` 字典，如 `{'registration_reviewed_at': '2026-08-31'}`；该值必须有业务来源，类型和必填性按新增 YAML 校验，读取来自新生成列。日期示例只用于独立造例，不要求青禾无依据填写。核心类名和核心映射是本版固定接口，任意新增类／重命名关系需要课程底座适配，不属于本周任务。

生成 ORM、JSON Schema 和对象库在 prepared/objects；它们可删除重建，不放客户手写规则。旧 ontology.yaml 保留财务、订单、卡、限制和知识等更广关系说明，export 自动附执行源指针和摘要；不要求再人工写第二份模型。它不是 executable model，无法替代源 YAML。

错误定位：MODEL_TODO_FILL_CUSTOMER_SOURCE 表示列表未填；MODEL_REQUIRED_CLASS 表示删掉核心类；INSTANCE_INVALID 包含类、数据行及字段错误；MISSING_REFERENCE 表示关系目标不存在；REGISTRATION_PROVENANCE_MISMATCH 表示会员关系与来源注册关系不符；SOURCE_MUST_HAVE_ONE_FINANCIAL_OWNER 表示账户财务归属不唯一。模型／代码／状态／生成物改变后需使用新 prepared 与 home 重建，不能复用旧绑定。
