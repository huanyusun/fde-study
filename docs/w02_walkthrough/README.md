# W02 完整操作导航

工程包 `w02-agent-0.5.4`，作业采用自然语言业务模型。具体任务、三位必访与提交标准以外层课程材料的作业任务书为准；这里说明操作顺序。

1. 保留 W1 客户仓库和提交快照，将 W2 工程解压到新目录。按[根 README](../../README.md)安装依赖，并从[模型配置与恢复](../model-configuration.md)选择适合自己端点的配置及超时设置。可以用各命令的 `--workspace` 指向原客户仓库，不覆盖前周工程。
2. 在访谈网站完成自己的访谈并导出“提取用记录”，保存到客户仓库。网站不由本包部署，账号窗口按通知。
3. 按[持续提取工作流](../w02_workflow/README.md)初始化，填写自己的材料、本轮目标和提取问题；Agent 读取 Skill、调用工具后，在人工核查停点查看原文并给出反馈。[提取命令](../w02_extraction/README.md)也可单独使用。
4. 对照模型修改前后，必要时退回草稿修订，确认后保存两份文档。再按[自然语言知识入口](../w02_knowledge/README.md)运行 `w02_knowledge.py init`，保留已有文档并关联采用的提取运行；多次提取时显式指定本轮记录。干系人地图仍放在访谈记录中。
5. 从自己的材料选取问题，运行 `w02_knowledge.py compare`。问题检验自己的业务定义、关系或流程，避免提前列出预期答案。检查实际请求和回答，在既有访谈记录中说明客户知识带来的具体变化；有问题再修改重跑。
6. 对照 W1 fit-gap，沿用编号、保留快照，只修订受新增证据影响的条目。运行[公开预检](../w02_check/README.md)，按反馈补齐，再提交客户仓库。

两份人工文档是 `docs/w02/business_model.md` 和 `docs/w02/interview_notes.md`。配置或代码、原始访谈、候选 JSON、文档版本及实际请求回答是同一仓库的支撑记录，由工具尽量自动留存。不要提交模型凭据、虚拟环境或不相关的本地资料。

[图书馆工作流示范](../../examples/w02_workflow/README.md)用于理解和环境检查，无需完整重复其运行作为额外必交。示例、原始客户记录、真实模型调用和教师判读各自说明来源；旧例子不能充当自己的青禾答案。

当前仅提供本地运行与证据预检，不自动向平台上传或打分。正式提交渠道、截止日期及访谈窗口以班期通知为准。
