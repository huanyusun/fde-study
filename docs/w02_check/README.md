# W02 公开预检

`w02-checker-0.2.0`。默认检查“两份人工文档＋程序运行记录”，不执行学员代码，不判定作业通过。

```sh
.venv/bin/python tools/check_w02.py --workspace /path/to/客户仓库 --output artifacts/w02/precheck-v1.json
```

省略 workspace 时使用工程目录；报告路径须为新文件，不覆盖旧反馈。路径已存在时，本次结果仍显示在终端，但不保存，并提示换一个新路径重新运行。默认读取 `customer/w02/knowledge.json`，可用 `--config` 指定；自动寻找 `artifacts/w02/knowledge_runs/` 下的运行。

检查两份文档、采用的实际提取、原始来源及三位必访覆盖、业务模型版本与同题对照、W1 fit-gap 的接续。候选里有没有冲突、文档是否只是模板、来源是否支持定义，以及 Agent 回答是否正确，都保留在九项人工审阅队列中。

结果为 `needs_revision` 或 `ready_for_review`，后一项只表示结构与记录关联可供审阅。所有人工项仍为 pending；哈希、live 标签和模型回答不证明身份、真实执行或业务正确，需要时由教师复跑。

修改业务模型后重新对比，不覆盖原运行。有正确对照时不要求制造错误。失败和单次调试记录可以保留，不计为同题对照；旧版本记录不计当前模型覆盖。若无可用对照，报告会提示重新运行 `compare`。自动找到的运行超过 100 条时，报告列出 `RUN_LIMIT_EXCEEDED` 并跳过逐条检查，其余项目照常检查；这时用重复的 `--run` 选择实际采用的一组，不要求手写运行编号。

`--w1-fit-gap` 可指定前周提交快照；存在 `artifacts/w02/product_fit_gap.json` 时自动检查原编号仍保留。没有受影响条目时在访谈记录说明即可，不要求再生成一份相同清单。
