# 青禾指标构建方法

## 一、目标与输入
按输入的目标 ID 逐项处理，不新增、不改名、不遗漏。三类输入职责不同：业务模型提供对象、关系、粒度和经访谈确认的业务规则（如付费资格的卡范围、有效期端点）；客户材料提供报表口径（统计对象、计入排除、日期归属、分母为零的处理）；字段字典提供实际列名和单位（金额为整数分）。先区分"材料没给定义"和"字典没给字段"：定义缺失列未决，字段缺失检查是否确有物理列可用，都不凭常识补。已由客户材料明确写出口径的指标，直接采用该口径并引用原文；不得凭指标名称猜口径，不得加入资料没有提出的规则。

## 二、候选及依据
为每个目标整理：统计对象与粒度、统计时间、计入与排除条件、金额或数量构成、聚合方式、单位。每一项都要在输入中找到依据。catalog 的 sources 使用输入文件名和连续原文 quote，引文必须逐字出现在该文件中，并能支持对应的定义；一个目标需要多条依据时分列多条，不拼接、不改写。business_model_usage 只记录实际采用的业务模型原句。涉及资格、首购、月内口径的目标，先确认三件事都有依据：判断对象、判断时点或历史范围、计入排除条件；缺任何一件即按第五段处理，不用自己的解释顶替。

## 三、字段与计算转换
按已核实的粒度写 measure：行级表达式只使用字典中存在的列，字段名逐字使用，不因改单位而改字段名。计入与排除条件写进行级表达式：状态、金额为正等条件不满足时计 0 或不入聚合；取消单按字典约定其金额列为 0，仍须保留状态条件，不得依赖数值巧合。金额类指标逐项核对计入项与扣减项（如实付、退款、原价的组合）；退款按业务口径归属到原订单统计时间，数据中退款列挂在订单行上，按下单时间统计即自然归属，不得改用其他时间。比率与均值类指标先确认分子分母的构成与量纲，再确认分母为零的处理：业务口径为"分母零时未定义"的，用派生计算表达为 NULL（空值），不得输出 0、无穷大或报错当作正常值；这类多阶段转换交给第六段派生模型或派生 measure 完成。单位分两层：底层计量单位（count、cents、ratio）与展示单位分开核对，目录单位必须与量纲一致。

## 四、依赖与输出协议
比率指标用 ratio 类型引用已定义的指标 ID；当零分母须表达为 NULL 时，用派生模型上的 CASE 表达式 measure 替代原生 ratio，并在指标描述中写明分母为零时返回空值的口径，两条路线都保持依赖闭合。measure 名称全局唯一。月度人数、月度付费会员类指标按材料要求设置 query_policy.full_month_only 为 true 且不接受维度筛选时，在 constraints 写明仅完整自然月、全门店全渠道；通用指标为 false。catalog 只收录已定义指标，未决目标不得进入 catalog；catalog 每项给出 id、name、aliases、unit、constraints、sources、query_policy。model_sql 只用于派生 SQL 模型。只返回一个 JSON 对象，包含 semantic_models、metrics、catalog、model_sql、grain_keys、unresolved、business_model_usage，不返回 Markdown 或 YAML。输出前逐项自查：本批全部目标的依赖在本批闭合；同一目标不在已定义与未决两处出现。

## 五、未决、冲突与修订
资料缺少某个目标的定义，或材料之间、材料与访谈确认之间说法冲突时，把该目标列入 unresolved，写明缺什么依据或冲突在哪里、影响哪部分计算、向哪位已确认角色核实（负责人与问题写入 reason），不要为了覆盖目标而补写公式。每个目标只能出现在已定义或未决其中一边。资格类规则（卡范围、端点、判定日、提前终止）以业务模型中记录的客户确认为准；业务模型未记录的资格规则一律未决，不按行业习惯或字段名替客户决定。维度确实缺少关系依据时，用 dimension_id、missing_facts、reason 说明，不虚构连接。

## 六、语义模型与派生模型
把业务对象映射到语义模型：订单一行一单、会员一行一账户、门店一行一店、卡一行一卡；输入 access_tables 是原样接入表，time_spine 由框架按覆盖期提供，不预置任何业务排序、月表或资格列。已确认关系映射为实体主外键：订单挂会员账户（外键）与成交门店（外键）；会员挂归属门店（另一角色）；卡挂会员账户（一对多）。同一物理门店表承担成交门店与归属门店两个角色时，分别建语义角色，不复制数据。逐个核对 dimension_targets：实体查询 ID 对应实体名，属性查询 ID 用主实体名__维度名，局部维度名不带双下划线。

先声明一行代表什么，再写聚合。每个模型的 grain_keys 给出实际粒度列名列表；单键按主键检查，组合粒度逐列检查，不能用吞空值的拼接逃避检查。主实体无重复无空值；外键指向同业务对象的唯一实体；一对多关联（订单→卡、会员→卡）先在目标粒度上汇总或判定存在，再把结果接回主体，不得把卡行直接关联进订单或会员后求和、计数——资格判定按"账户 × 月"先判定，多卡取并集语义（任一符合条件的卡即成立）时在账户月粒度表达 EXISTS 或布尔聚合，不放大行数。

三类多阶段规则的方法：
1. 首购排序类：历史范围以材料口径为准（观测期首购以测试覆盖期全期历史确定首次，再按查询窗口筛选），不能让本次窗口悄悄改变历史排序。先形成每个账户的候选有效订单集合，按统计时间排序、相同时间按业务确认的次级排序键打破并列，取首单形成账户一行，再按首单日期落入窗口计数或求和。
2. 按期汇总类：期间边界按材料口径（自然月，结束日不含），归期时间按业务确认（如下单日期）。先聚合到"账户 × 月"或"门店 × 日"等目标粒度，再在该粒度上判断（如月内有效订单达到两笔为复购），最后回到指标粒度计数；月内人数类指标不得跨月加总，跨多月查询按月分别展示。
3. 资格判断类：判定对象（账户）、判定时点（自然月最后一天）、事实来源（卡表）、多卡重叠处理、端点规则（开始/结束/终止日当天是否有效）全部从业务模型与材料取得并引用原文；得到"账户 × 月"资格结果后接回同粒度计算。资格规则任何一件缺依据即整族未决。

需要上述派生结果时，先用 model_sql 生成派生 SQL 模型（SELECT/WITH 与 {{ ref('...') }}，不覆盖接入模型与 time_spine，不使用文件、网络、DDL、DML），再为派生结果建语义模型；派生表与原表是不同行集合，为派生表声明自己的主实体名与 grain_keys，不与原表复制同一主实体/时间维度配对。时间维度使用字典日期列或派生表的非保留日期列名；day、month、year、metric_time 是保留名，不得用作实体或维度名；有 dimensions 的模型必须声明 primary 实体或 primary_entity。比率分母为零须为 NULL 的，在派生模型上用 CASE WHEN 表达式 measure 实现，分子分母保持与已定义基础指标相同的计入条件。每个引用的依赖必须在本次输出内闭合，否则相关指标列未决。business_model_usage 的 used_for 写 kind 与 name，quote 为业务模型连续原文；不把构建检查或自己的推断写成客户事实。
