# 青禾指标构建方法

## 一、目标与输入
按输入的目标 ID 逐项处理，不新增、不改名、不遗漏。三类输入职责不同：业务模型提供对象、关系、粒度和经访谈确认的业务规则（如付费资格的卡范围、有效期端点）；客户材料提供报表口径（统计对象、计入排除、日期归属、分母为零的处理）；字段字典提供实际列名和单位（金额为整数分）。先区分"材料没给定义"和"字典没给字段"：定义缺失列未决，字段缺失检查是否确有物理列可用，都不凭常识补。已由客户材料明确写出口径的指标，直接采用该口径并引用原文；不得凭指标名称猜口径，不得加入资料没有提出的规则。

## 二、候选及依据
为每个目标整理：统计对象与粒度、统计时间、计入与排除条件、金额或数量构成、聚合方式、单位。每一项都要在输入中找到依据。catalog 的 sources 使用输入文件名和连续原文 quote，引文必须逐字出现在该文件中，并能支持对应的定义；一个目标需要多条依据时分列多条，不拼接、不改写；每个目录项 sources 最多三条，选最能支持口径的原文，不凑数。business_model_usage 只记录实际采用的业务模型原句。涉及资格、首购、月内口径的目标，先确认三件事都有依据：判断对象、判断时点或历史范围、计入排除条件；缺任何一件即按第五段处理，不用自己的解释顶替。

## 三、字段与计算转换
按已核实的粒度写 measure：行级表达式只使用字典中存在的列，字段名逐字使用，不因改单位而改字段名。计入与排除条件写进行级表达式：状态、金额为正等条件不满足时计 0 或不入聚合；取消单按字典约定其金额列为 0，仍须保留状态条件，不得依赖数值巧合。金额类指标逐项核对计入项与扣减项（如实付、退款、原价的组合）；退款按业务口径归属到原订单统计时间，数据中退款列挂在订单行上，按下单时间统计即自然归属，不得改用其他时间。比率与均值类指标先确认分子分母的构成与量纲，再确认分母为零的处理：业务口径为"分母零时未定义"的，不得输出 0、无穷大或报错当作正常值。单位分两层：底层计量单位（count、cents、ratio）与展示单位分开核对，目录单位必须与量纲一致。

## 四、依赖与输出协议
基础计数与金额指标是 simple 指标，引用下方第三段钉板 measure；比率与均值指标一律用 derived 指标表达，input metrics 用同批已定义的基础指标名，expr 统一为 `case when <分母指标> = 0 then null else <分子指标> / <分母指标> end`——数据库对 0/0 会输出 nan 而不是空值，必须用 CASE 显式置 null，禁止用原生 ratio 类型承载"分母零时未定义"的口径。derived 指标引用的每个指标名必须在同一批输出内定义，否则该指标列未决；本批不定义的基础指标不重复定义（跨批重复定义会在合并时报重复名）。月度人数、月度付费会员类指标在 catalog 设 query_policy.full_month_only 为 true 且 constraints 写明 ["仅完整自然月","全门店全渠道"]；通用指标 full_month_only 为 false、constraints 为 []。catalog 只收录已定义指标，未决目标不得进入 catalog；catalog 每项给出 id、name、aliases、unit、constraints、sources、query_policy。model_sql 只用于派生 SQL 模型。输出必须是裸 JSON：第一个字符是 `{`，最后一个字符是 `}`；不用代码块围栏或任何代码块标记，JSON 之后不得再写说明、注释或任何文字；不是 Markdown 也不是 YAML。输出对象只含 semantic_models、metrics、catalog、model_sql、grain_keys、unresolved、business_model_usage 七个键。输出前逐项自查：本批全部目标的依赖在本批闭合；同一目标不在已定义与未决两处出现。

本批输入只给了部分目标时，其余目标既不定义也不未决，直接不在输出中出现，也不要输出任何解释未批目标的文字。

## 五、未决、冲突与修订
资料缺少某个目标的定义，或材料之间、材料与访谈确认之间说法冲突时，把该目标列入 unresolved，写明缺什么依据或冲突在哪里、影响哪部分计算、向哪位已确认角色核实（负责人与问题写入 reason），不要为了覆盖目标而补写公式。每个目标只能出现在已定义或未决其中一边。资格类规则（卡范围、端点、判定日、提前终止）以业务模型中记录的客户确认为准；业务模型未记录的资格规则一律未决，不按行业习惯或字段名替客户决定。维度确实缺少关系依据时，用 dimension_id、missing_facts、reason 说明，不虚构连接。

## 六、语义模型与派生模型
业务对象映射：订单一行一单、会员一行一账户、门店一行一店、卡一行一卡；订单挂会员账户（外键）与成交门店（外键）；会员挂归属门店（另一角色）；卡挂会员账户（一对多）；同一物理门店表承担成交与归属两个角色，分建 stores_selling 与 stores_home。**五个接入语义模型（含全部 measure）逐字使用下面的 JSON，每个批次都原样输出，不得增删或改写字段、顺序或描述**——分批构建合并时同名模型必须逐字节一致：

先声明一行代表什么，再写聚合。每个模型的 grain_keys：orders→["order_id"]，members→["member_id"]，stores_selling→["store_id"]，stores_home→["store_id"]，cards→["card_id"]；派生模型给出实际粒度列名列表，主实体无重复无空值；一对多关联先在目标粒度上汇总或判定存在，再把结果接回主体，不得把卡行直接关联进订单或会员后求和、计数。派生模型的主实体名不得与任何接入模型实体名相同（避免外键目标歧义），派生表不与原表复制同一主实体/时间维度配对；day、month、year、metric_time 是保留名，不得用作实体或维度名；有 dimensions 的模型必须声明 primary 实体。

**simple 指标到 measure 的固定映射**（本批含该目标时才输出该指标定义；type simple、type_params 引用对应 measure）：`order_count`→order_count_measure、`paid_order_count`→paid_order_count_measure、`valid_order_count`→valid_order_count_measure、`cancelled_order_count`→cancelled_order_count_measure、`refund_order_count`→refund_order_count_measure、`partial_refund_order_count`→partial_refund_order_count_measure、`full_refund_order_count`→full_refund_order_count_measure、`payment_cents`→payment_cents_measure、`refund_cents`→refund_cents_measure、`net_sales_cents`→net_sales_cents_measure、`gross_cents`→gross_cents_measure、`discount_cents`→discount_cents_measure、`buyer_count`→buyer_count_measure、`refund_buyer_count`→refund_buyer_count_measure、`selling_store_count`→selling_store_count_measure、`valid_order_items`→valid_order_items_measure、`new_member_count`→new_member_count_measure。

**比率与均值目标固定为 derived 指标**（input metrics 为同批定义的基础指标）：`avg_order_value`＝net_sales_cents/valid_order_count、`avg_buyer_value`＝net_sales_cents/buyer_count、`purchase_frequency`＝valid_order_count/buyer_count、`refund_amount_rate`＝refund_cents/payment_cents、`cancel_rate`＝cancelled_order_count/order_count、`refund_order_rate`＝refund_order_count/paid_order_count、`discount_rate`＝discount_cents/gross_cents、`items_per_order`＝valid_order_items/valid_order_count、`monthly_repeat_rate`＝monthly_repeat_buyer_count/monthly_buyer_count、`monthly_paid_repeat_rate`＝monthly_paid_repeat_buyer_count/monthly_paid_buyer_count、`monthly_paid_avg_order_value`＝monthly_paid_sales_cents/monthly_paid_order_count。expr 均按第四段 CASE 模式。

三类多阶段规则的派生模型设计（model_sql 用 SELECT/WITH 与 {{ ref('orders') }}、{{ ref('members') }}、{{ ref('cards') }}、{{ ref('time_spine') }}，不覆盖接入模型与 time_spine，不使用文件、网络、DDL、DML）：

1. **首购排序类**（first_buyer_count、first_order_sales_cents、first_order_count、repeat_order_count）：观测期以测试覆盖期全期历史确定首次，再按查询窗口筛选。派生模型一 `orders_valid_ranked`：行级有效订单（paid 且实付-退款>0），加列 first_seq＝row_number() over (partition by member_id order by ordered_at, order_id)，主实体 first_ranked_order，时间维度 ordered_at，grain_keys ["order_id"]；度量 repeat_order_count＝count(case when first_seq > 1 then order_id end)。派生模型二 `member_first_valid_order`：从 orders_valid_ranked 取 first_seq＝1 每账户一行，列 member_id、first_ordered_at、first_net_cents，主实体 member_first_order，时间维度 first_ordered_at，grain_keys ["member_id"]；度量 first_buyer_count＝count(member_id)、first_order_count＝count(member_id)、first_order_sales_cents＝sum(first_net_cents)。两个派生模型都在本批输出。
2. **按期汇总类**（monthly_buyer_count、monthly_repeat_buyer_count、monthly_repeat_rate）：期间边界自然月、结束日不含，归期按下单日期。派生模型 `account_month_general`：有效订单按 member_id、date_trunc('month', ordered_at) 聚合，列 member_id、month_start、valid_order_cnt，主实体 account_month，时间维度 month_start，grain_keys ["member_id","month_start"]；度量 monthly_buyer_count＝count(member_id)、monthly_repeat_buyer_count＝count(case when valid_order_cnt >= 2 then member_id end)；monthly_repeat_rate 按第四段 derived 模式引用前两个指标，同一批输出。
3. **资格判断类**（monthly_paid_* 六项）：判定对象账户、判定时点自然月最后一天、事实来源卡表、多卡取并集（任一符合即成立）、端点规则（valid_from 当天起有效、valid_until 当天已无效、ended_at 当天起无效）、卡范围悦享年卡+家庭季卡，全部按业务模型与材料 04 的原文引用。派生模型 `account_month_paid`：time_spine 的 date_day 按 date_trunc('month') 生成覆盖期内每个自然月 m0 与月末末日 m_last（m_last＝m0 当月最后一天），先取"账户 × 月"并判定资格：exists(select 1 from cards c where c.member_id＝账户 and c.card_type in ('悦享年卡','家庭季卡') and c.valid_from <= m_last and (c.valid_until is null or m_last < c.valid_until) and (c.ended_at is null or m_last < c.ended_at))，再只保留有资格账户，接回该账户当月有效订单聚合，列 member_id、month_start、valid_order_cnt、net_cents_sum，主实体 account_month_paid，时间维度 month_start，grain_keys ["member_id","month_start"]；度量 monthly_paid_buyer_count＝count(member_id)、monthly_paid_order_count＝sum(valid_order_cnt)、monthly_paid_sales_cents＝sum(net_cents_sum)、monthly_paid_repeat_buyer_count＝count(case when valid_order_cnt >= 2 then member_id end)；monthly_paid_repeat_rate、monthly_paid_avg_order_value 按第四段 derived 模式引用，同一批输出。资格规则任何一件缺依据即整族未决。

派生表与原表是不同行集合，为派生表声明自己的主实体名与 grain_keys。比率分母为零须为 NULL 的口径在指标描述中写明。每个引用的依赖必须在本次输出内闭合，否则相关指标列未决。business_model_usage 的 used_for 写 kind 与 name，quote 为业务模型连续原文；不把构建检查或自己的推断写成客户事实。

**批次纪律**：每个批次都输出第五段全部五个接入语义模型（逐字一致）＋本批目标的指标定义与目录；批次只按目标 ID 划分，派生模型只属于其目标所在批次，不提前输出后续批次的派生模型。
