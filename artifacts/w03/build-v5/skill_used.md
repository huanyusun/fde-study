# 青禾指标构建方法

## 一、目标与输入
按输入的目标 ID 逐项处理，不新增、不改名、不遗漏。三类输入职责不同：业务模型提供对象、关系、粒度和经访谈确认的业务规则（资格、端点、判定时点等）；客户材料提供报表口径（统计对象、计入排除、日期归属、分母为零的处理）；字段字典提供实际列名和单位。先区分"材料没给定义"和"字典没给字段"：定义缺失列未决，字段缺失检查是否确有物理列可用，都不凭常识补。已由客户材料明确写出口径的指标，直接采用该口径并引用原文；不得凭指标名称猜口径，不得加入资料没有提出的规则。**客户的状态、金额构成、日期、卡种与资格等事实一律以输入为准，本文件不预设任何具体值；构建每个目标时回到材料与业务模型取原文。**

## 二、候选及依据
为每个目标整理：统计对象与粒度、统计时间、计入与排除条件、金额或数量构成、聚合方式、单位。每一项都要在输入中找到依据。catalog 的 sources 使用输入文件名和连续原文 quote，引文必须逐字出现在该文件中，并能支持对应的定义；一个目标需要多条依据时分列多条，不拼接、不改写；每个目录项 sources 最多三条，选最能支持口径的原文。business_model_usage 只记录实际采用的业务模型原句；本批没有采用业务模型内容时输出空数组，绝不为凑数编造或改写引文。涉及资格、首购、月内口径的目标，先确认三件事都有依据：判断对象、判断时点或历史范围、计入排除条件；缺任何一件即按第五段处理，不用自己的解释顶替。

## 三、字段与计算转换
按已核实的粒度写 measure：行级表达式只使用字典中存在的列，字段名逐字使用。计入与排除条件逐字取材料口径写进行级表达式；状态条件不得因数值上恰好为 0 而省略。金额类指标逐项核对计入项与扣减项；退款按业务口径归属到原订单统计时间，数据中退款列挂在订单行上，按下单时间统计即自然归属，不得改用其他时间。聚合方式与统计对象一致：计数类满足条件取键列否则为空、金额类不满足条件取 0。**凡材料口径含"不同账户数""不同门店数"等去重词义的指标，聚合必须用 count_distinct 施加于对应实体键——count(行数)给出的是订单数或事件数，不是人数；两者数值不同，选错聚合是口径错误。**生成后逐项自查：人数→实体键去重、门店数→门店键去重、件数→求和、单数→计数；不做跨系统自然人合并。比率与均值类先确认分子分母构成与量纲，再确认分母为零的处理：材料口径为"分母零时未定义"的，不得输出 0、无穷大或报错当作正常值；数据库对 0 除会返回 nan 而非空值，必须用显式 CASE 置空（见第四段）。单位分两层：底层计量单位（count、cents、ratio）与展示单位分开核对，目录单位必须与量纲一致。

## 四、依赖与输出协议
基础计数与金额指标是 simple 指标，type_params 引用对应 measure 名。比率与均值指标一律用 derived 指标表达：形状 `{"name":<目标id>,"type":"derived","type_params":{"expr":"case when <分母指标> = 0 then null else <分子指标> / <分母指标> end","metrics":["<分子指标>","<分母指标>"]}}`——引用列表的键名是 `metrics`（旧写法，不是 input_metrics），expr 中写指标名；分子分母必须是同批已定义的指标 ID，依赖必须在本次输出内闭合，否则该指标列未决；不重复定义其他批已定义的基础指标。原生 ratio 类型无法表达"分母零输出空值"，禁止用于承载该口径。指标定义对象只含 name、label、description、type、type_params，不得夹带 query_policy 或 constraints——查询限制只写在 catalog 条目上：月度人数、月度付费会员类指标在 catalog 设 query_policy.full_month_only 为 true 且 constraints 写明仅完整自然月、全门店全渠道；通用指标为 false、constraints 为空。catalog 只收录已定义指标，未决目标不得进入 catalog；catalog 每项给出 id、name、aliases、unit、constraints、sources、query_policy。model_sql 只用于派生 SQL 模型。输出必须是裸 JSON：第一个字符是 `{`，最后一个字符是 `}`；不用代码块围栏，JSON 之后不得再写任何文字，输出完对象立即停止；不是 Markdown 也不是 YAML。输出对象只含 semantic_models、metrics、catalog、model_sql、grain_keys、unresolved、business_model_usage 七个键。输出前逐项自查：本批全部目标的依赖在本批闭合；同一目标不在已定义与未决两处出现。

本批输入只给了部分目标时，其余目标既不定义也不未决，直接不在输出中出现，也不要输出任何解释未批目标的文字。输出在足以支持核查的前提下保持精炼：指标 description 一句话写口径（比率加"分母为零时未定义"）；语义模型 description 一句话写行粒度；目录 sources 最多两条，选最能支持口径的原文；不输出与结构和口径无关的解释性长文。

## 五、未决、冲突与修订
资料缺少某个目标的定义，或材料之间、材料与访谈确认之间说法冲突时，把该目标列入 unresolved，写明缺什么依据或冲突在哪里、影响哪部分计算、向哪位已确认角色核实（负责人与问题写入 reason），不要为了覆盖目标而补写公式。每个目标只能出现在已定义或未决其中一边。资格类规则（卡范围、端点、判定日、提前终止）以业务模型中记录的客户确认为准；业务模型未记录的资格规则一律未决，不按行业习惯或字段名替客户决定。维度确实缺少关系依据时，用 dimension_id、missing_facts、reason 说明，不虚构连接。

## 六、语义模型与派生模型
把业务对象映射到语义模型：订单一行一单、会员一行一账户、门店一行一店、卡一行一卡；已确认关系映射为实体主外键——订单挂会员账户（外键）与成交门店（外键），会员挂归属门店（另一角色），卡挂会员账户（一对多）。同一物理门店表承担成交门店与归属门店两个角色时，分别建两个语义模型，不复制数据。四张接入表对应的接入语义模型（门店因双角色为五个）必须完整输出，每个模型含 name、model（ref('接入表名')）、entities、dimensions，有统计时间的给 defaults（agg_time_dimension 用字典日期列）和 measures；语义模型与度量全部由本调用生成。

原生配置约束：dimensions[].name 只填属性局部名，不把双下划线查询 ID 填进 name；一个实体名只能有一个 primary/unique 目标，其他关联用 foreign；同一实体和维度名配对唯一；主实体表达式列必须单独无重复无空值，账户×月这类组合粒度在派生 SQL 中生成单列代理键（由非空列构成，粒度检查会验证空值与重复），或按框架支持的方式声明组合粒度，不用会吞空值的拼接逃避检查。派生模型主实体名不得与任何接入模型实体名相同；派生表与原表是不同行集合，为派生表声明自己的主实体与时间维度，不复制原表配对。day、month、year、metric_time 是保留名，不得用作实体或维度名；时间维度用字典日期列或派生表的非保留日期列，在 defaults.agg_time_dimension 引用；metric_time__day／month 仅作查询目标 ID。有 dimensions 的模型必须声明 primary 实体。逐个核对 dimension_targets：实体查询 ID 对应实体名，属性查询 ID 用主实体名__维度名，维度必须能沿已确认关系从指标实际查询。

先声明一行代表什么，再写聚合。每个模型的 grain_keys 给出实际粒度列名列表，组合键逐列列出，不填 SQL 表达式。一对多关联先在目标粒度上汇总或判定存在，再把结果接回主体，不得把卡行直接关联进订单或会员后求和、计数——资格判定按"账户×判定期"先判定，多卡取并集语义（任一符合条件的卡即成立）时在该粒度用 EXISTS 或布尔聚合表达，不放大行数。

三类多阶段规则的派生方法（派生模型名称自行选择，须唯一且不与接入实体重名；model_sql 仅用 SELECT/WITH 与 {{ ref('...') }}，不覆盖接入模型与 time_spine，不使用文件、网络、DDL、DML；凡 model_sql 中出现的派生模型，必须同批输出其语义模型定义与 grain_keys 条目，grain_keys 键集合与本批 semantic_models 名称集合完全一致）：

1. **首购排序类**：历史范围以材料口径为准（观测期首购以测试覆盖期全期历史确定首次，再按查询窗口筛选），不能让本次窗口悄悄改变历史排序。先形成每账户候选有效订单集合，按统计时间排序、相同日期按材料确认的次级排序键打破并列；第一笔构成账户一行的首单表（首单日期、首单净额），第二笔及以后构成订单粒度的后续购买集合，各自按其统计日期落窗计数或求和。首购人数、首单数、首单净额挂账户粒度首单表；后续购买订单数挂订单粒度表。
2. **按期汇总类**：期间边界按材料口径（自然月、结束日不含），归期时间按业务确认。先聚合到"账户×月"粒度并判定（如月内有效订单达到两笔为复购），再在该粒度上计数；月内人数不得跨月加总，跨多月查询按月分别展示。
3. **资格判断类**：判定对象（账户）、判定时点（材料指定的月末判定日）、事实来源（卡表）、多卡重叠处理（并集）、端点规则（开始/结束/终止日当天是否有效）与卡范围**全部先从业务模型与材料 04 的原文取得并引用**，业务模型未记录即整族未决。用 time_spine 生成覆盖期内各自然月及月末判定日，先得"账户×月"资格结果，再接回同粒度的当月有效订单聚合。比率分母为零须为空值的口径在指标描述中写明。

business_model_usage 的 used_for 写 kind 与 name，quote 为业务模型连续原文；不把构建检查或自己的推断写成客户事实。

**批次纪律**：维度目标是批级检查，每批指标须能解析全部维度目标，因此默认一次生成完整库，不按族分批；仅当试跑小批（全部挂在接入模型上）时用 --metrics，此时同样完整输出全部接入语义模型与本批引用的派生模型。
