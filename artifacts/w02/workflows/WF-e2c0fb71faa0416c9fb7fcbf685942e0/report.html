# W2 业务模型说明：青禾会员运营

## 要回答的问题与范围
本轮从 W2 五人访谈（小林/陈姐/老周/王经理/沈总）提取会员运营业务知识，回答：口径定义、活动流程与角色分工、痛点期望、投入效果判断标准、旧项目使用情况。条件为五次访谈的自述，接受整理不等于独立核实客户业务事实。本模型用于理解“需关注会员如何形成有依据的建议，并经运营与门店确认后执行”。本周不接入客户数据、不计算复购率、不开发触达工具。W1 接续与 Agent 验证结果写在 `docs/w02/interview_notes.md`。

## 对象、属性与关系
**会员**：老周要求区分付费会员卡与免费注册会员（CLM-001-0017，访谈者复述后老周确认无出入；仍为同一来源的角色陈述、未经独立数据验证），描述会员时须分开；不据此推断两类互斥或穷尽全部会员分类。全量会员数（老周口径 120 万，系统全量）≠ 活跃会员；两者不能混用（CLM-001-0018）。120 万数字本身未独立核实；老周本人目前没有可确认的活跃会员统计（不能推断公司无人掌握或统计不存在），活跃口径须按核查对象和用途对应实际记录确定。
**订单**：分线上与门店渠道，谈订单范围须先说清渠道（CLM-001-0017）。
**优惠券**：发放与核销是两个环节，发放记录不能替代核销记录；具体状态和口径还得核实（CLM-001-0017，按原话记一条未知，不扩展为券业务整体未知）。
**会员标签**：系统有标签字段，含义需结合实际填写方式核实；维护人不掌握（CLM-001-0019，双未知）。
**活动安排**：运营（小林）发起 → 陈姐（门店）接收执行 → 执行反馈回传小林。
**小林的 Excel**：小林手工维护一份 Excel，有些工作会绕开系统、用这份账来做事（CLM-001-0001，两次一致陈述）；表内具体字段与名单筛选规则未知（CLM-001-0002）。

## 规则、条件与候选动作
**活动流程（均为角色自述做法，不代表公司成文规定）**：
- 小林路子：先看未完成运营任务和反馈→明确这次面向哪些会员、准备做什么→与相关同事确认线上/门店执行→执行中记录进度和问题→结束后整理反馈和未核实效果信息（CLM-001-0004）。具体筛人条件需对实际记录核实；人群与执行方案最终须业务人员确认（MSG-02941/02943）。
- 小林↔陈姐：门店执行安排找陈姐确认；先说清面向哪些会员、做什么，再确认门店怎么执行、谁来配合；执行中跟进进度反馈，记录对不上找陈姐核对（CLM-001-0005、CLM-001-0006）。线上渠道对接人未知。
- 陈姐接收：先核对三件事——面向哪些会员、哪些门店参与、门店具体要做什么，再向门店同事说明并确认人员与执行安排（CLM-001-0009，MSG-02956/02968 两次一致）。
- 陈姐执行：收集顾客问题和门店反馈，不清楚找运营核对，结束后整理执行情况；活动安排与现场反馈对接小林；具体怎么记、怎么发属未知，需按实际沟通记录核实（CLM-001-0010）。
- 陈姐处理规则：顾客在线等时先照常接待、核清适用范围、运营确认后才向顾客说明；不能因线上可见就认定门店可执行（CLM-001-0012）。适用范围/门店要做多少/现场问题找谁答不清时，先要求澄清、不默认门店已接受；影响门店考核的安排先调整再执行（CLM-001-0013，兼作门店侧执行前澄清规则）。
- 老周协作规矩：问题、数据范围、用途、需谁配合说清才核；材料不够或口径对不上退回继续确认；不先把系统数字当最终答案（CLM-001-0016，作为我方提交核对材料的流程约束）。
- 小林期望（候选动作边界）：助手先整理需关注会员、每条建议写清依据（为什么列入、依据哪些情况），减少重复整理核对；人群与执行方案仍需业务人员确认。**动作边界（当前权限状态）：未获授权前系统不得自动发券、联系会员、改记录，仅做整理与写依据——不代表客户不要这些能力，后续周可再确认授权**（CLM-001-0007，FDE 修正记录）。

**投入与效果判断**：
- 王经理看三块：业务要做什么、钱准备花在哪些地方、效果怎么说明；功能数量与财务效果分开看（CLM-001-0022）。
- 要求材料：试点范围说明、费用构成及依据、双方工作与责任草案、效果记录方案；未谈妥金额指标一律标待确认、不写成承诺（CLM-001-0023，作为我方准备材料的直接依据）。
- 财务效果定义：与投入费用对应、可量化、留下记录，非功能清单数量；具体指标与计算口径待双方谈定。防误读声明照原话保留：这说的是她核查时看什么，不代表她认定某功能无效；我方不将此条解读为任何功能无效判断（CLM-001-0025）。观察点设计约束：须可量化、留记录、与费用对应。这些是她说明的核查要求，不能组合成公司正式的继续推进或审批充分必要条件。项目组可以提出带条件继续核实的建议，但是否继续、范围及授权仍须相关方共同确认。
- 王经理权限边界：可提核查意见、可要求补充、可暂缓财务确认；预算额度、签约、验收、续约不能凭访谈替公司承诺；实际审批人与授权额度按未知保留待核（CLM-001-0024）。
- 沈总目标：复购率止跌回升为项目核心目标，期望三个月内见阶段性进展、向董事会交代——记为期望而非已定验收标准；幅度与口径明示未定（CLM-001-0026、CLM-001-0028）；排期由老周牵头、小林配合提出，目前尚未有人提出。
- 沈总安排：复购口径核对老周牵头、小林配合、算法项目组共同核实——访谈中单方提出，尚未向老周/小林回传确认，落实待定（CLM-001-0027）。
- 沈总叫停条件：①业务问题、依据与待核项说不清；②试点范围与配合没说法；③几方各说各话且无人讲清依据、说好谁补材料——沈总个人在访谈中提出的条件，非公司正式规则或已核实授权制度；兼作我方提交材料自检清单（CLM-001-0029）。

## 建模选择：把建议、安排、执行与效果分开

下表是基于角色说法作出的建模选择，用来组织认识，不宣称客户系统已有这些表或字段。

| 对象 | 当前定义与需要表达的属性 | 与其他对象的关系及用途 |
| --- | --- | --- |
| 会员 | 被关注、被建议或参与活动的业务对象；会员类型、统计范围需明确；是否“活跃”及选入规则仍待核实 | 建议指向会员；活动可面向一组会员。不能直接把全量会员当活动人群 |
| 运营建议 | 提议关注谁、建议做什么、为什么列入及依据哪些情况；尚未执行 | 建议关联会员及依据，由业务人员确认人群与方案。一个会员可能有多次建议，不把“会员”与“一条建议”混为一物 |
| 活动安排 | 一次拟开展的会员活动安排；需描述面向人群、活动内容、参与门店、门店任务、配合人及答疑对接 | 从建议到活动安排须经业务确认；安排传给陈姐进一步核对，发送安排不代表门店已接受 |
| 门店执行与反馈 | 某次活动在某门店的执行情况、进度、问题及反馈；具体记录方式未知 | 同一次活动可能涉及不同门店，线上可见不推出任一门店适用。执行反馈关联活动及门店，经陈姐与小林核对，不能直接充当核销或复购效果 |
| 效果观察 | 用来说明活动或试点产生什么结果的记录；指标、算法、时间窗与基线尚待谈定 | 财务侧要求与费用对应、可量化并留记录。建议已生成、活动已安排都不能替代效果证据 |
