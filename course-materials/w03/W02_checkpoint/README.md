# W2 checkpoint：参考答案

> 课程方参考稿，2026-10-27。对应 W02 工程包 `w02-agent-0.5.4`、W02 任务书 v0.17。只使用 W2 访谈中所有同学都能取得的信息、旧项目结项材料与背景补充，以及 W1 checkpoint；不含 W3 及以后才讨论的内容。

本目录是 W2 的完整参考交付，供没有完成 W2 的同学在 W3 接续，也供完成了的同学对照。已经完成 W2 的，继续用自己的文档和记录，不要用它覆盖自己的文件。

## 包含什么

目录结构就是一个按 W2 任务书提交的客户仓库：

| 位置 | 内容 |
| --- | --- |
| `docs/w02/business_model.md` | 参考业务模型说明 |
| `docs/w02/interview_notes.md` | 参考访谈与核查记录：访谈目标、干系人地图、核查取舍、分歧、方法开发与验证、Agent 判读、W1 接续 |
| `customer/w02/` | 提取配置、修改后的提取提示词和 Skill、工作流任务、知识配置 |
| `artifacts/w02/sources/` | 课程方的 W2 原始访谈导出（老周、小林两场、陈姐、沈总、王经理） |
| `artifacts/w02/runs/` | 全部提取运行，包括失败的几次；采用哪一次见访谈与核查记录第五节 |
| `artifacts/w02/workflows/` | 一次未完成的持续工作流，保留作方法验证记录 |
| `artifacts/w02/knowledge_runs/` | 同题对照：同一问题在未提供、提供业务模型时的实际请求和回答 |
| `artifacts/w02/product_fit_gap.xlsx`、`.json` | W2 版 fit-gap，在 W1 checkpoint 的 5 条上修订，编号不变 |
| `artifacts/w01/product_fit_gap.json` | W1 checkpoint 的 fit-gap，原样保留，作为 W1 快照 |

在 W02 工程目录运行 `tools/check_w02.py --workspace 本目录`，预检结果为 `ready_for_review`。

## 怎样接到 W3

1. 把 `docs/w02/business_model.md` 复制为自己仓库的 `docs/w03/business_model.md`，作为 W3 工作副本的起点；W2 原版保持不动。
2. 按 W3 任务书第 1 步建立 W3 工作副本，再用 W2 提取工具结合本周访谈更新模型。业务模型第五节的未知和分歧，正是 W3 要继续核实的问题。
3. 在 W3 的记录中写明：起点采用了本参考稿，以及采用了哪些部分。

## 使用时注意

- **不能代替自己的 W2**。照抄参考答案不算完成 W2。这里的访谈是课程方做的，不能当作你的访谈成果；三位必访、提取方法、核查、同题对照都要用自己的记录完成。
- **参考访谈只覆盖一部分方向**。访谈问到了什么、没问到什么，见访谈与核查记录第一节。你自己的访谈问到更多内容时，按自己的记录建模。
- **方法记录包括失败**。几次失败的提取运行、未完成的工作流都保留了，原因和改法写在访谈与核查记录第五节，可以对照自己遇到的问题。
- **模型配置要换成自己的**。课程方用的是课程网关，提取配置 `profile` 为 `gateway-json`，这是针对该网关的设置。你用自己的模型时，按工程内 `docs/model-configuration.md` 选择匹配的 profile。
- **判断要自己负责**。参考答案是一种合理的判断，不是唯一答案。W3 取得新证据后，按证据修订，并写出理由。
