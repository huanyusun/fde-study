# C02｜AIG：沿着材料流找到要问的人

行业：保险。案例类型：客户内部 AI 应用。首次主讲：W2；本次使用：W2；重点：进场、需求。W3 再讨论效果指标与比较口径。

> 案例手册 v0.5｜2026-09-19｜公司公开披露、教师分析与教学虚构分别标明。

面对一个不熟悉的行业，可以先找一份实际业务材料，追踪它从哪里来、经过谁处理、最后支持什么判断。这个案例用于练习怎样沿着材料找到访谈对象，并把“希望客户介绍业务”改成有明确证据目标的问题。

**阅读视角**：借已投产的应用，倒推建设之前需要弄清的业务认识。下文的问题按事前调查设计，部分也适用于上线后的回访；它们是教师设计的问题，不是 AIG 的原始访谈记录。

## 一、六格概览：哪些过程有依据

| 进场 | 需求 | MVP |
| --- | --- | --- |
| 内部承保应用；首周访谈安排未披露 | 提取关键字段，补充信息形成摘要，并按承保偏好安排处理优先级 | 已披露投产应用；首版最小可行产品的范围未披露 |

| 变更 | 验收 | 沉淀 |
| --- | --- | --- |
| 披露了扩大应用范围的安排；具体需求变更单未披露 | 投产状态有依据；正式签字与合同验收门槛未披露 | 未披露可直接复用的客户交付资产 |

上述概览依据 AIG 的[2025 投资者日材料](https://www.sec.gov/Archives/edgar/data/5272/000000527225000017/aig_investorxdayx2025.htm)第 120～121 页，表示材料发布时的披露范围。

**本周判断（教学分析）**：材料的提供者、使用者和系统维护者掌握的信息不同。访谈需要分别取得材料来源、业务含义与处理规则，再核对这些说法能否相互支持。

## 二、先看懂应用进入了什么工作

**公司与项目（公司公开披露）**：AIG 是一家为企业和个人提供保险服务的全球保险集团。AIG Underwriter Assistance 是供承保人员使用的内部 AI 辅助应用，由 AIG 与 Palantir、Anthropic 等伙伴共同建设，并使用 AWS 的相关服务。AIG 提供保险业务知识、目标和数据；Palantir 支持数据整合、模型接入与编排；Anthropic 提供 Claude 模型；AWS 提供相关云与文档处理服务。上述为公开合作与技术组成，不能据此确定完整实施分工。来源：[AIG 官方公司介绍](https://www.aig.com/home/about)、[AIG 投资者日材料，第 116、125 页](https://www.sec.gov/Archives/edgar/data/5272/000000527225000017/aig_investorxdayx2025.htm)。

**业务释义**：承保人员需要了解保险申请、评估风险，再推进后续业务。本案例中的经纪人负责向保险公司提交材料；submission 在课堂中指供承保评估使用的一组文件与信息，不预设为一张格式统一的表。

**原有工作（公司公开披露）**：经纪人提交的文件进入承保处理流程。AIG 介绍了数据分散、材料差异及人工处理带来的困难，原有工作包括人工提取、检查细节、查询内部与外部信息、补充资料，再由承保人员填写费率计算工具并启动审批。来源：[AIG 投资者日材料，第 111～112 页](https://www.sec.gov/Archives/edgar/data/5272/000000527225000017/aig_investorxdayx2025.htm)。

**AI 参与后的工作（公司公开披露）**：AIG Underwriter Assistance 的三项能力是提取关键字段、补充信息并形成摘要、安排处理优先级。应用提取经纪人、被保险人名称、地址等字段，结合内部与外部的相关信息形成摘要，并按承保偏好安排处理优先级；示意图区分了时间排序与承保偏好排序。AI 给出结果后，承保人员仍要分析输出，再进入后续业务。来源：[AIG 投资者日材料，第 116～117、120 页](https://www.sec.gov/Archives/edgar/data/5272/000000527225000017/aig_investorxdayx2025.htm)。

**建设原则与披露范围（公司公开披露）**：建设原则包括围绕具体业务问题、与业务共同建设、人工参与监督和改进。2025 年投资者日材料将该应用标为已投产，第 121 页限定为美国部分 Financial Lines 业务，扩大部署另列为推进中的工作，不代表最新全球部署状态。来源：[AIG 投资者日材料，第 114、120～121 页](https://www.sec.gov/Archives/edgar/data/5272/000000527225000017/aig_investorxdayx2025.htm)。这些公开流程提供了调查线索，具体分工、权限与例外仍需核实。

**以下为教学分析**。把调查落在输入材料、处理过程和结果使用上，可以分别问清这些问题：

| 调查位置 | 需要弄清什么 | 为什么要问到具体工作 |
| --- | --- | --- |
| 输入材料 | 谁提供，谁整理，版本怎样更新，缺项怎样补齐 | “已经收到文件”不能说明内容完整、版本一致或含义明确 |
| 提取字段 | 原文写了什么，字段描述哪个主体、与本次申请是什么关系，采用哪个值还需什么依据 | 提取成功不代表业务含义已经确认 |
| 补充信息 | 补充资料对应哪个时间、覆盖什么范围，能否用于当前申请 | 找到相关资料不代表它适用于这次判断 |
| 使用摘要 | 摘要支持哪项具体判断，哪些信息和条件必须保留 | 摘要是否有用，要看使用者能否据此开展下一步工作 |
| 安排优先级 | 找到了解并维护条件的人、实际使用排序的人，用规则说明、处理记录与例外样例核对排序依据 | 处理顺序不能直接等同于最终承保决定 |
| 人工判断 | 三项能力之后，结合权限说明、操作记录和异常样例，单独核实谁能决定继续、要求补充或转交 | AI 参与信息整理，不代表业务判断也已自动化 |

这张表是一份调查框架。公开介绍给了我们工作线索，具体角色分工和处理规则仍要通过访谈与材料核查取得。

## 三、先选一项已处理的申请，找到实际经手人

**本节为课堂调查设计**。面对前面的公开流程，可以先想一个起步动作：向客户要什么材料，希望联系谁？

一个可行的起点，是请客户对接人协助，取得一项获准使用、已经处理过的申请及相关补充记录，再联系实际整理或使用过这些材料的人。选已处理的申请，可以把收到的文件、补充过程、实际用途和继续或暂停的条件对应起来；一项申请先提供入口，适用范围还需其他样例核对。

围绕这一次处理，请经手人说明：材料从哪里来，自己做了什么处理，结果交给谁，支持什么判断。需要取得的依据包括提交样例、附件清单、补充或修订记录，以及实际处理过程和判断依据。对方不能解释原始信息，就继续找申请方的相关经手人；系统版本无法解释，则找数据与技术协作人员核对记录。

“你们最需要什么功能”可以得到需求方向，但仍需追问最近一次具体工作。角色提出“自动整理”后，可以继续问：整理到什么程度才可用，使用者还要补做什么，遇到哪些情况必须回到原材料核查。不同角色尽量围绕同一项申请说明，避免每换一个角色就换一个互不相关的样例。

**本课未取得 AIG 的真实申请样本或原始访谈**。公开流程只能帮助定位应向客户索取的材料；暂时拿不到样例时，先确认可提供的材料范围和实际经手人，记录调查缺口。

访谈记录中也要保留回答的性质。亲历者描述的工作、角色对原因的解释、FDE 根据多个线索作出的推断，需要分别记录；暂时没有材料支持的判断，写清下一步向谁核实。

## 四、调查短题：面对两份材料，下一步找谁、问什么

**以下任务、材料、企业名称和人物均为教学虚构，不是 AIG 的真实记录或字段规则；本题不新增提交项**。

**任务**：调查这份情况说明能否用于本次申请摘要。你尚未访谈任何人。

| 已取得的摘录 | 内容与来路 |
| --- | --- |
| 申请表 | “被保险人名称”为“青松贸易有限公司”，由经纪人小林为本次申请提交 |
| 情况说明 | 名称写为“青松贸易”，由小林从此前往来邮件转发；摘录未标明对应哪次申请，也未注明资料覆盖的期间 |

原邮件与完整附件尚未取得。目前可以联系三个人：

| 联系人 | 已知职责 |
| --- | --- |
| 小林，经纪人 | 整理并提交这次材料 |
| 小周，承保人员 | 将使用申请摘要 |
| 小陈，数据工程师 | 负责文件入库与版本关联 |

**先自行判断，再看参考判读**：

1. 选一个起步动作：先联系谁，围绕哪个疑点怎样问？
2. 希望取得什么依据，用来核实什么？
3. 哪些结论还不能下，需要保留哪些原值、来源和未知？

### 参考判读

**先核实什么，决定这一步找谁；不同起点可以成立，但要说明依据**。

| 联系对象与核实目标 | 可以怎样问 | 希望取得的依据与边界 |
| --- | --- | --- |
| 先找小林，核对材料来路 | 这份说明为什么放进本次申请？原来对应什么事情、哪个期间？ | 原邮件、完整附件及本次选用记录，再核对主体、时间与业务范围是否适用 |
| 先找小周，核对业务用途 | 准备用这份说明作什么判断，满足哪些条件才能使用？ | 一次处理过程与判断依据；随后仍需向小林核对材料来路 |
| 找小陈，核对系统记录 | 文件怎样入库，版本怎样关联？ | 入库与版本记录；归到同一申请不能单独证明内容适用于本次业务判断 |

目前只知道两个名称写法不同，说明由此前邮件转来。名称相似不能证明同一主体，来自此前邮件也不能直接判定资料过期。主体对应、资料期间与本次适用性都要继续核实，先保留原值、来源和未知。

判读看的是选择是否有线索支持、问题能否取得具体依据，以及有没有把未知提前当成结论。只答“不能合并”、直接判定资料过期，或没有依据地指定唯一访谈顺序，都没有完成这道题的调查判断。

**合理性追问（教学假设）**：假设业务人员拿到摘要后仍回看原材料，可能是在确认主体与范围，也可能需要反复寻找出处。必要的业务核对与额外查找负担可以同时存在。应继续了解这次回看在确认什么、为什么目前这样处理，以及哪些条件明确后才能继续。这个假设不证明 AIG 存在上述具体问题，也不足以决定取消核查或开发某项功能。

### 把材料线索变成可执行的调查

**以下为教学归纳，不是 AIG 项目组织图**。

| 材料线索 | 需要核实什么 | 找谁 | 希望取得什么依据 |
| --- | --- | --- | --- |
| 提交与补充 | 信息从哪里来，补过什么 | 实际整理或提供材料的人 | 原始样例、附件与补充记录 |
| 摘要、排序与人工判断 | 支持什么决定，条件与例外是什么 | 实际使用结果、维护规则的人 | 处理过程、规则说明与判断依据 |
| 补交与版本变化 | 系统怎样关联、保存和传递更新 | 数据与技术协作人员 | 版本关联方式与实际记录 |

这三类职责不是固定三个人，也不是固定顺序。无法解释就继续找实际经手人，缺少依据就保留待核。一个可以开始的动作，需要说清围绕什么材料、找谁核实什么、希望取得什么依据。

这个练习留下了需要表达清楚的对象、含义与关系：申请、相关主体、提交文件分别指什么，名称怎样解释，两份文件及其中的名称是什么关系。两份文件有关联，不等于其中的信息可以直接合并。V04 学习业务本体的基础概念，并用独立的图书馆例子展开建模；后续再抽取候选信息、对照证据修订认识，并检查 Agent 是否正确使用这些定义和未知项。完整实体解析的方法留到 W5，本周先做到准确表达当前认识。

## 五、课后对照：迁移到青禾优选

**本节供课后自选对照，不新增必做练习或提交项**。青禾的业务与保险承保不同，可以借鉴的是沿材料调查的办法。具体权限、岗位立场和业务定义，要回到本周材料及自己的访谈记录。

| 可借鉴的方法 | 在青禾怎样使用 |
| --- | --- |
| 从材料找人 | 从旧项目结项材料中选出一项待核说法，判断谁能解释、谁能提供依据 |
| 从一次工作追问 | 请受访者描述最近一次相关操作，追问输入、处理、例外和结果去向 |
| 追问当前做法的原因 | 先问为什么这样处理，再判断是障碍、合理业务选择还是尚缺条件；说明需要谁提供什么依据 |
| 对照不同角色的说法 | 核对各方谈的是不是相同时间、范围和定义，再判断是否存在冲突 |
| 把未知写成调查任务 | 说明尚缺什么依据，以及下一步向谁取得什么材料或数据 |

可以选一个自己已有的待核实问题，对照检查是否说清了“围绕什么材料、问谁、问什么、希望取得什么证据”。后续访谈取得的新发现，可按本周要求写入[访谈与核查记录](../06_访谈与核查记录模板.md)，其中包含干系人地图，并据此完善[业务模型说明](../07_业务模型说明模板.md)。完整任务、操作与提交统一以[作业任务书](../05_作业任务书.md)为准。

**迁移条件**：能够接触材料提供者和实际使用者，取得获准使用的具体材料，并保留不同说法及其来源。条件尚不具备时，先记录调查缺口。

**不能照搬**：保险行业的字段、承保判断和排序规则不能直接变成会员运营定义；一个应用已经投产，也不能证明青禾的输入条件、业务效果或系统接入已经成立。

## 六、课后自查与来源

| 自查问题 | 检查自己的回答 |
| --- | --- |
| 为什么先选一项已处理的申请？ | 是否能把文件、补充过程、实际用途和继续或暂停的条件对应起来，并保留用其他样例核对适用范围的需要 |
| 为什么要围绕同一材料问不同角色？ | 是否说清各方掌握的信息和需要取得的证据 |
