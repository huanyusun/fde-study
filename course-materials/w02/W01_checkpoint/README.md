# W1 checkpoint：参考答案

> 课程方参考稿，2026-10-23 修订（见文末“修订说明”），对应 fit-gap 契约 `w01-0.2.1`、产品 `0.2.0-w1`、能力矩阵 `w1-capabilities-0.2.0`。只使用 W1 材料、沈总在首轮访谈中的公开回答和标准产品文档，不含后续周才取得的信息。

本目录供没有完成 W1 的同学在 W2 接续使用。已经完成 W1 的，继续用自己的提交，不需要替换；想对照可以读，但不要用它覆盖自己的文件。

## 包含什么

| 文件 | 内容 |
| --- | --- |
| `artifacts/w01/product_fit_gap.xlsx` | 参考 fit-gap 填写稿，5 条判断，编号 `GAP-001`～`GAP-005` |
| `artifacts/w01/product_fit_gap.json` | 由 W1 转换工具从上面的填写稿生成 |
| `docs/w01/project_assessment.md` | 参考立项分析报告 |

不包含环境检查、模型基线和运行证据。这三份 W1 产出物必须用自己选择的模型实际运行生成。

## 怎样接到 W2

1. 把 `artifacts/w01/` 下的两个文件和 `docs/w01/project_assessment.md` 复制到自己客户仓库的同名路径。
2. W2 第 5 步需要修订 fit-gap 时，把 `artifacts/w01/product_fit_gap.json` 复制为 `artifacts/w02/product_fit_gap.json`，沿用原编号直接修改；W1 的原文件保留不动。
3. 在 W2 的访谈与核查记录中写明：W1 起点采用了本参考答案，以及采用了哪些部分。

## 使用时注意

- **不能代替自己的 W1**。照抄参考答案不算完成 W1。沈总访谈、立项判断和三份运行证据仍要按 W1 任务书补齐。
- **证据要换成自己的**。证据明细里标为“沈总首轮访谈（参考稿占位）”的行没有具体消息位置。W2 可以继续约沈总核实 W1 的问题；访谈后换成自己记录中的消息位置，没有访谈就删除这些行。
- **判断要自己负责**。参考答案是一种合理的初步判断，不是唯一答案。你在 W2 取得新证据后，按证据修订分类和证据状态，并写出理由。

## 修订说明（2026-10-23）

第一版有两处口径不一致，这一版改正：

1. **有几行写的不是客户诉求**。原来的“复购率口径”“验证会员老化”是待核项，“接入青禾数据”是实施前提；沈总的第一件事“把复购下滑解决掉”反而没有单独成行。这一版每行对应一项客户诉求，按沈总邮件分成结果期望、运营诉求和使用诉求；会员老化、80 万、四个季度下滑这些信息假设不单独成行，写进报告第三、六节和相关条目的下一步。
2. **证据状态评的对象前后不一致**。原来有的行评客户说法，有的行评产品侧事实。这一版统一为：证据状态描述这一行判断的依据有多硬。一行判断要对上两头：客户这头，要什么、口径和条件是什么；产品这头，现在能做什么。哪一头还只靠某个角色没核实的说法，就记角色转述；两头都有可以核对的材料，才记已核实；关键依据谁都没说清，记未知。适配分类是拿这两头对照出来的，只看产品能力不够。

报告另外补了三处：标准产品现在能做什么、做不到什么；客户口径（复购率）和产品口径（净消费）之间的转换；沈总问的“能先验证哪一部分”。结论不变。
