# 青禾优选：会员运营助手本轮新增需求

> 需求材料 v0.3｜2026-10-14。承接第一次 demo，已补齐本轮主条件及业务依据的使用原则；v0.3 增加第五节，列明本轮按条件筛选会员支持和不支持的条件。配套记录和工程已随本轮材料包提供。本文不是已签 SOW 的替代文本。

## 一、本轮要解决的问题

现有查询能力可以回答指标问题。运营接下来希望把查询结果用于会员工作：找到需要关注的人，查看相关信息和记录，说明入选原因、使用限制和建议依据。门店也希望通过直接入口查看同一会员的信息。

本轮使用以下任务验证这些能力：

> 为指定门店找出符合本轮沉睡和消费条件的会员，查看其会员信息和关联记录，说明入选理由、触达限制及待核事项，并给出有依据的运营建议。

“沉睡会员召回”是本轮的代表性任务。交付关注的是约定范围内的会员运营助手能力，而不是预先写死的一份名单或一段只能完成一次的演示。更换已支持的条件时，应继续正确工作；遇到超出数据、功能或权限范围的要求，应说明缺口。

## 二、为什么需要补充旧 POS 数据

CRM 与旧 POS 并存。2025 年曾从旧 POS 迁入一部分会员，在 CRM 生成新账户，迁移前的消费仍留在旧 POS；未迁移会员也可能继续在旧 POS 消费。此前取得的 v1 数据只包含新 CRM 的消费记录。

因此，CRM 中查不到近期购买，不能直接说明一个人在所有系统中都没有购买。小林工作账中“仍用老卡购买”的反馈需要通过补充数据核实，既不能忽略，也不能仅凭自述认定原判断全部错误。

本轮要将有依据的新旧账户关联起来，使同一会员的已覆盖购买记录能够共同参与判断。关联依据不足或相互冲突时，应保留待核状态和来源，不能为了得到人数或名单而强行合并。旧 POS 的具体交付范围、字段和可使用的核查依据以配套数据说明为准。

## 三、需要补齐的能力

| 能力 | 希望得到的业务结果 | 核对重点 |
| --- | --- | --- |
| 新旧身份关联 | 能识别有依据属于同一会员的来源账户，并关联其记录 | 能追溯来源及依据；未决身份与已确认身份可以区分 |
| 按条件筛选会员 | 根据门店及本轮沉睡、消费等条件形成名单 | 条件明确、计算可核对；保留已有指标定义，说明身份粒度变化 |
| 查看会员及关联记录 | 可以查看会员基本信息、来源账户及已提供的订单、门店、会员卡等必要关系 | 信息有来源和覆盖范围；未知或冲突不会被补写成确定事实 |
| 提供解释与建议 | 说明为什么入选、有哪些限制、依据哪些业务信息提出建议 | 建议对应实际会员和查询证据，遵守已明确的触达限制，保留待核事项 |
| 多入口复用 | 运营 Agent 与门店直接入口可以取得一致的会员信息和关联记录 | 相同条件和数据版本下结果一致，能够单独核对业务能力的结果 |

青禾现有系统是 CRM、旧 POS。供不同入口共同调用的会员业务能力是本项目新增部分，不要求通过本轮完成 CRM 改造或新的门店系统上线。技术实现与课程方测试入口由配套工程说明交代。

## 四、业务条件怎样使用

本轮计算的固定参考日为 **2026-09-01**。近 12 个月净消费的时间窗口为 **2025-09-01（含）至 2026-09-01（不含）**；消费按已核定的净额口径处理，扣除退款，取消订单不计，异常退款先隔离。在完成身份关联后，合计已覆盖的新旧记录，并说明未覆盖或未决部分的影响。

W04 的历史工作账仍按每条“拉名单日期”计算，不用本轮参考日重新解释当时的名单。工作账里的分组和习惯是已有业务信息，不自动等同于本轮所有筛选规则。

本轮主任务采用以下条件。条件应能在已支持范围内调整，不能写死为某一份名单。

| 条件 | 本轮采用的含义 |
| --- | --- |
| 消费 | 近 12 个月净消费不少于 3,000 元，合计同一会员在已覆盖 CRM／旧 POS、门店及渠道的记录 |
| 沉睡 | 存在有效购买，且距参考日最近一次有效购买已满 60 天；支付有效、实付大于退款才算有效购买 |
| 门店 | 按来源账户的注册门店关系确定单店范围，同一人可关联多店，单店名单去重；购买门店不能代替注册门店，全公司人数不能直接相加各店人数 |
| 运营排除 | 经业务证据确认的员工、异常身份不进入本轮运营推荐；不删除其源记录，也不改变既有经营指标 |
| 联系限制 | 在已确认的统一身份下合并各来源限制；明确“请勿再联系”限制本轮所有渠道，“勿打电话”“勿发短信”只限制相应渠道。未指定渠道时分别说明，不默认电话 |
| 待核 | 身份、必要覆盖、核验结论或限制范围不明时保留待核，不当成零、正常或许可 |

导出覆盖内没有有效购买记录，不等于从未购买，也不能自动归入沉睡。POS 独有会员缺少注册门店时保留未知：全公司数据保留，单店结果说明这一范围缺口，不将全部未知会员重复列入每家店的待核名单。

具体依据分别见[身份关联与数据使用说明](03_身份关联与数据使用说明.md)、[运营对象核验说明](04_运营对象核验说明.md)及[联系限制与建议说明](05_联系限制与建议说明.md)。说明规定记录的使用原则，不代替配套记录本身；尚未收到、不能定位或存在冲突的依据不能假设已经核实。

已提供的材料可以直接作为依据。涉及身份线索及数据覆盖的问题向老周核实；涉及联系限制和运营例外的问题向小林核实；门店使用问题由陈姐说明，目标与优先级由沈总确认，合同范围问题按王经理职责核查。按实际缺口定向沟通，不要求所有信息重新访谈一遍。

## 五、按条件筛选会员：本轮的条件范围

沉睡召回是代表性任务，不是筛选能力的边界。本轮按下表的范围交付和验收：在范围内更换条件、阈值、时间或门店，属于正常使用，应继续正确工作。范围外的要求，助手应说明哪一项不能处理，不能去掉这一项后照常给出名单；是否纳入后续范围，按变更另行确认。

| 本轮支持的条件 | 怎样使用 |
| --- | --- |
| 按会员计算的指标 | 例如近 12 个月净消费、有效订单数。1～3 条同时满足，同一指标可以设上下限；使用两期对比时，可以不另设指标条件 |
| 统计时间 | 任意起止日期，含起始日、不含结束日，须在已覆盖的数据范围内 |
| 最近一次有效购买距参考日 | 可以不限，也可以设至少满 N 天、不足 N 天或一个区间 |
| 注册门店 | 一家、多家（最多 50 家）或全公司；多家门店合并时同一会员只列一次 |
| 会员等级 | 一个或多个等级；各来源等级不一致或没有等级记录的会员列为待核，不直接排除 |
| 注册日期 | 某日期之前、之后或一个区间；注册日期未知的会员列为待核，不直接排除 |
| 同一指标的两期对比 | 本期比基期下降或上升不少于给定比例，可以要求基期不低于某个值。只适用于可以累加的指标，例如净消费、订单数；客单价这类比率指标和月度类指标不能用于对比。基期须早于本期；对比范围是基期有记录的会员，本期没有记录的按零计算；基期为零或负数的不计算比例 |
| 联系渠道 | 电话、短信、两者都看，或不指定 |

本轮不支持：会员卡相关条件（卡种、购卡金额、生效或到期日期）；条件之间的「或」；除两期对比外，在一次筛选中使用多个时间段；只按完整自然月计算的月度类指标作筛选条件；超过 3 条指标条件；不带任何指标条件、只按等级或门店等属性列出会员；以 2026-09-01 以外的日期作为参考日。

只设上限的指标条件（例如净消费不足 1,000 元），名单只包含统计时间内有消费记录的会员，结果会说明这一范围；查找很久没有购买的会员，应使用最近一次有效购买的条件。

## 六、本轮边界与验证方向

本轮只读取、分析并提出建议，不执行自动触达、发券或标签写入，不承诺复购提升幅度。是否联系、怎样执行仍由业务人员确认。

验证应覆盖：正常名单和空名单；同一会员存在多个来源账户；身份依据不足或冲突；数据覆盖不足；明确不能联系或条件未核定的情况。数据与依据已随包提供，具体操作样例见作业任务书；预期应根据记录和规则自行核对，不预设人数或正确名单。

能力需要在约定条件变化时仍然成立，已有查询能力也应保留。是否属于新增范围，要核对实际增加的数据、能力、接口、权限、动作、规模或责任，不仅依据场景名称判断。已签条款仍以双方签署版本为准，未取得的条款不作推定。
