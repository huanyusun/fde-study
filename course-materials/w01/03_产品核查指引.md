# 产品核查指引

> 来源标识：`PRODUCT-W01-001`。适用产品 `0.2.0-w1`，能力矩阵 `w1-capabilities-0.2.0`。

工程 ZIP 中的 README 说明安装、模型配置、运行和已知限制；`product/capabilities.json` 是该版本能力矩阵，`product/API.md` 说明数据、HTTP 接口、动作约束及扩展边界。本页只给阅读顺序，不另复制一份能力清单。

先用自己选择的真实模型运行松果生活样例：比较 2026 年 7 月与 8 月的老会员消费，核对下降名单、前后金额、建议和依据。再运行缺时间澄清、S03 覆盖缺失和只读拒绝；在独立样例动作模式中查看草案，确认后通过 HTTP 执行、查询并撤销标签。基础评估与运行记录一起保留。

读代码时沿请求入口、用户时间范围、模型工具选择、参数与权限检查、SQLite 查询和结果回填走一遍，再看 checkpoint、确认和动作账本。区分真实模型、机制测试与故障注入，不能混成同一份效果证据。

做 fit-gap 时，每条判断回答四件事：客户具体要求什么；你依据哪个能力 ID 和什么实际证据；这项工作初步属于哪类；下一步怎样确认或处理。处理分类为“产品已有、客户配置、系统适配、产品缺口、暂不承诺”，分类依据不足时可标“待判断”。W01 形成初步版，不要求每类凑一条，也不按代码多少判断优劣；填写、转换与后续修订规则统一见[作业任务书](05_作业任务书.md)。

材料包已提供 fit-gap 空白表，填写位置与转换方法见[作业任务书](05_作业任务书.md)。

产品可以查询样例表，不表示已经接入青禾优选的数据；可以提出工具调用，不表示已经具备客户允许的业务写操作；一次执行结束，也不表示它证明了业务效果。这些差别需要通过运行记录、能力限制和客户证据说明。

允许自选模型、后端语言或从零实现等价底座。选择不同，验收路径和证据要求不变；不得用固定回答冒充实时 Agent，也不因为自研底座免除客户交付任务。
